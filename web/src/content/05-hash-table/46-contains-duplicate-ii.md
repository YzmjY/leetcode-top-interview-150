# 46. 存在重复元素 II

## 题目描述

给你一个整数数组 `nums` 和一个整数 `k`，判断数组中是否存在两个 **不同的索引** `i` 和 `j`，满足 `nums[i] == nums[j]` 且 `abs(i - j) <= k`。

**示例 1：**

```
输入：nums = [1,2,3,1], k = 3
输出：true
```

**示例 2：**

```
输入：nums = [1,0,1,1], k = 1
输出：true
```

**示例 3：**

```
输入：nums = [1,2,3,1,2,3], k = 2
输出：false
```

**约束条件：**

- `1 <= nums.length <= 10^5`
- `-10^9 <= nums[i] <= 10^9`
- `0 <= k <= 10^5`

## 题目分析

### 算法思路

本题需要判断是否存在两个相等的元素，且它们的下标之差不超过 `k`。

使用哈希表记录每个元素**最近一次出现的位置**：

1. 遍历数组，对于当前元素 `nums[i]`：
   - 检查该元素是否已经在哈希表中出现过。
   - 如果出现过，计算当前位置与上一次出现位置的差值 `i - lastIndex`。
   - 如果差值 `<= k`，说明找到了满足条件的两个元素，返回 `true`。
   - 无论是否满足条件，更新该元素的最新位置为 `i`。

注意事项：即使当前差值 `> k`，也应该更新位置为当前 `i`，因为后续可能出现更近的重复元素。

### 为什么正确

遍历到下标 `i` 时，表中保存的是每个值**最近一次**出现的下标。若存在 `j < i` 使 `nums[j] == nums[i]` 且 `i - j <= k`，设 `j*` 是最近一次出现的下标，则 `j <= j* < i`，于是 `i - j* <= i - j <= k`，只检查最近一次出现就一定能发现；反之，若最近一次出现的距离都大于 `k`，更早的出现只会更远，更不可能满足。因此「查最近一次 + 判断距离」是充要条件，算法正确。不满足时仍需把下标更新为 `i`，因为对后续位置而言 `i` 是更近的一次出现。

### 复杂度分析

- **时间复杂度**：O(n)，只需遍历数组一次，哈希表操作均摊 O(1)。
- **空间复杂度**：O(n)。代码不淘汰过期记录，哈希表最多装入数组中的每个**不同**元素（例如全不相同的数组会存 n 条），因此最坏是 O(n)。若改成维护一个大小为 `k+1` 的滑动窗口（每步删除下标为 `i-k-1` 的旧记录，或用窗口内计数），空间可降到 O(min(n, k))，本题不需要这么做。

### 易错点 / 边界情况

- 距离判据是 `i - idx <= k`，等号成立也算满足（题目要求 `abs(i-j) <= k`）。
- 不满足条件时也要更新 `lastIndex[num] = i`，否则后续更近的重复会被漏掉。
- `k = 0` 时任何不同下标对的距离都 `>= 1 > 0`，答案必为 `false`。
- 比较的是下标之差，不是数值之差。
- 数值范围含负数和大数（`-10^9` 到 `10^9`），用 `map[int]int` 不受影响。
- 只需记录最近一次出现的位置即可，不需要保存所有历史下标；保存多个位置反而增加空间。
- 单元素数组直接返回 `false`。

## Go 代码实现

```go
func containsNearbyDuplicate(nums []int, k int) bool {
    // 哈希表：元素值 -> 最近一次出现的下标
    lastIndex := make(map[int]int)

    for i, num := range nums {
        // 检查该元素之前是否出现过
        if idx, ok := lastIndex[num]; ok {
            // 下标差是否在 k 以内
            if i-idx <= k {
                return true
            }
        }
        // 更新该元素的最新位置
        lastIndex[num] = i
    }

    return false
}
```
