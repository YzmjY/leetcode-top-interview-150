# 126. 颠倒二进制位

## 题目描述

颠倒给定的 32 位无符号整数的二进制位。

**提示**：
- 请注意，在某些语言（如 Java）中，没有无符号整数类型。在这种情况下，输入和输出都将被指定为有符号整数类型，并且不应影响您的实现，因为无论整数是有符号的还是无符号的，其内部的二进制表示形式都是相同的。
- 在 Java 中，编译器使用二进制补码记法来表示有符号整数。因此，在**示例 2**中，输入表示有符号整数 `-3`，输出表示有符号整数 `-1073741825`。

### 示例 1

```
输入：n = 00000010100101000001111010011100
输出：964176192 (00111001011110000010100101000000)
解释：输入的二进制串 00000010100101000001111010011100 表示无符号整数 43261596，
     因此返回 964176192，其二进制表示形式为 00111001011110000010100101000000。
```

### 示例 2

```
输入：n = 11111111111111111111111111111101
输出：3221225471 (10111111111111111111111111111111)
解释：输入的二进制串 11111111111111111111111111111101 表示无符号整数 4294967293，
     因此返回 3221225471，其二进制表示形式为 10111111111111111111111111111111。
```

### 约束条件

- 输入是一个长度为 `32` 的二进制字符串。

## 题目分析

### 算法思路

**朴素想法**：把 32 位二进制串写出来（`fmt.Sprintf("%032b")`），反转字符串再解析回整数。能过，但多花了 O(32) 的字符串空间和解析开销，不是位运算解法。

**关键观察**：`result` 每左移一位，就把之前已经收集好的位整体向高位推一格、最低位空出来；此时把 `num` 当前的最低位移入 `result` 的最低位，再让 `num` 右移一位，就完成了一次「从低位到高位」的搬运。重复 32 次，`num` 的第 `i` 位正好落到 `result` 的第 `31-i` 位。

**算法步骤**：

1. `result = 0`。
2. 循环 32 次，每次：
   - `result <<= 1` 腾出最低位；
   - `result |= num & 1` 把 `num` 的最低位放进 `result` 的最低位；
   - `num >>= 1` 处理下一位。
3. 返回 `result`。

**为什么正确（循环不变量）**：设已循环 `t` 次（`0 <= t <= 32`），则此时 `result` 的低 `t` 位恰好是原 `n` 低 `t` 位的逆序，且 `num == n >> t`。初始 `t = 0` 时 `result = 0`、`num = n`，不变量成立。每轮把 `result` 左移一位，其原有的低 `t` 位整体上移到第 `1..t` 位，再填入 `num` 的最低位（即原 `n` 的第 `t` 位），于是低 `t+1` 位成为原 `n` 低 `t+1` 位的逆序；`num >>= 1` 后恰好等于 `n >> (t+1)`。循环 32 次后，`result` 的低 32 位就是原 `n` 的 32 位逆序。

**方法二（分治 / 掩码交换）**：把整个 32 位串分成两块，依次按 16、8、4、2、1 的宽度做「块内两半互换」，每一步都修正一批位置错误的位对：

- `num = (num >> 16) | (num << 16)`：交换高 16 位与低 16 位；
- `((num & 0xff00ff00) >> 8) | ((num & 0x00ff00ff) << 8)`：以 8 位为块，块内交换两半；
- 再依次用 `0xf0f0f0f0/0x0f0f0f0f`、`0xcccccccc/0x33333333`、`0xaaaaaaaa/0x55555555` 处理 4、2、1 位。

5 步之后全部 32 位逆序完成，常数只有约 5 步而不是 32 步。

### 复杂度分析

- **时间复杂度**：O(1)，两个方法都只做固定次数的位运算（方法一 32 次，方法二 5 组操作）。
- **空间复杂度**：O(1)，只用了常数个变量。

### 关键点

- 循环次数必须固定为 32，不能写成 `for num != 0`：那样会把高位的 0 丢掉。例如 `1` 反转后应是 `1 << 31`，而不是 `1`。
- `num >>= 1` 必须是逻辑右移。`uint32` 无符号，`>>` 天然是逻辑右移；若用有符号类型会变成算术右移，高位补 1 导致结果错误。
- `num` 与 `result` 都用 `uint32`，语义与题面一致，也避免 32 位之外的高位干扰。
- 方法二的掩码必须成对互补（如 `0xff00ff00` 与 `0x00ff00ff`），写错掩码会得到「看起来合理」的错误结果。
- 结果必须补满 32 位：示例 1 的 `964176192` 最高位是 0，但它仍是完整的 32 位表示，不能当成 30 位数处理。
- 输入为 0 时，32 轮循环会不断左移 0，返回 0，正确；不要为「提前结束」做优化。

## Go 代码实现

```go
package main

import "fmt"

func reverseBits(num uint32) uint32 {
    var result uint32 = 0
    for i := 0; i < 32; i++ {
        result <<= 1         // 左移腾出位置
        result |= num & 1    // 取 num 的最低位放入 result
        num >>= 1            // num 右移
    }
    return result
}

// 分治法（更高效）
func reverseBits2(num uint32) uint32 {
    num = (num >> 16) | (num << 16)
    num = ((num & 0xff00ff00) >> 8) | ((num & 0x00ff00ff) << 8)
    num = ((num & 0xf0f0f0f0) >> 4) | ((num & 0x0f0f0f0f) << 4)
    num = ((num & 0xcccccccc) >> 2) | ((num & 0x33333333) << 2)
    num = ((num & 0xaaaaaaaa) >> 1) | ((num & 0x55555555) << 1)
    return num
}

func main() {
    var n1 uint32 = 43261596
    var n2 uint32 = 4294967293

    fmt.Printf("输入:  %032b (%d)\n", n1, n1)
    fmt.Printf("输出:  %032b (%d)\n", reverseBits(n1), reverseBits(n1))

    fmt.Printf("输入:  %032b (%d)\n", n2, n2)
    fmt.Printf("输出:  %032b (%d)\n", reverseBits(n2), reverseBits(n2))
}
```
