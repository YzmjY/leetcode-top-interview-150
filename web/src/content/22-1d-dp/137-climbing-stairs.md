# 137. 爬楼梯 (Climbing Stairs)

## 题目描述

假设你正在爬楼梯。需要 `n` 阶你才能到达楼顶。

每次你可以爬 `1` 或 `2` 个台阶。你有多少种不同的方法可以爬到楼顶呢？

**示例 1：**

```
输入：n = 2
输出：2
解释：有两种方法可以爬到楼顶。
1. 1 阶 + 1 阶
2. 2 阶
```

**示例 2：**

```
输入：n = 3
输出：3
解释：有三种方法可以爬到楼顶。
1. 1 阶 + 1 阶 + 1 阶
2. 1 阶 + 2 阶
3. 2 阶 + 1 阶
```

**约束条件：**

- `1 <= n <= 45`

## 题目分析

### 算法思路

**朴素想法**：把「爬 n 阶」按最后一步分解为「先爬到 n-1 阶再爬 1 阶」和「先爬到 n-2 阶再爬 2 阶」，于是 `f(n) = f(n-1) + f(n-2)`，可以直接递归。但递归会大量重复计算同一个子问题，是指数级；改成自底向上递推即可。

**方法：斐波那契递推（DP）**

- **状态定义**：`dp[i]` = 爬到第 i 级台阶（第 i 级是终点）的方法数。
- **状态转移**：要到达第 i 级，最后一步只能是从第 i-1 级爬 1 阶，或从第 i-2 级爬 2 阶。这两类方案互不重叠（最后一步长度不同），且合起来覆盖所有方案，所以 `dp[i] = dp[i-1] + dp[i-2]`。
- **边界条件**：`dp[0] = 1`（站在地面视为一种方案，它是 `dp[2] = dp[1] + dp[0]` 成立所必需的），`dp[1] = 1`。

**为什么正确**：对整个递推做归纳。i = 1、2 时手工验证（分别为 1 种、2 种）。i ≥ 3 时，按最后一步的长度把所有爬法分成「最后一步 1 阶」和「最后一步 2 阶」两类，两类分别与「爬到 i-1」「爬到 i-2 的方法」一一对应，由加法原理和归纳假设得 `dp[i] = dp[i-1] + dp[i-2]`。答案即 `dp[n]`。

**空间优化**：`dp[i]` 只依赖前两个状态，因此不必开数组，用两个变量 `prev2 = dp[i-2]`、`prev1 = dp[i-1]` 滚动更新即可。代码中 n ≤ 1 时直接返回 1，等价于 `dp[0] = dp[1] = 1`。

### 复杂度分析

- **时间复杂度**：O(n)，从 2 到 n 走一遍，每次 O(1)。
- **空间复杂度**：O(1)，只用了两个滚动变量。

### 关键点

- 边界 `dp[0] = 1` 容易写成 0，会导致 n = 2 时答案错误；它表示「不爬也是一种方案」。
- 这是最经典的 DP 入门题，体现「最优子结构 + 重叠子问题」；滚动变量的模板适用于所有只依赖前几项的一维 DP。
- n ≤ 45 时答案最大为 1836311903，仍在 32 位有符号整数范围内，不需要 int64。

## Go 代码实现

```go
package main

func climbStairs(n int) int {
    if n <= 1 {
        return 1
    }

    // prev2 = dp[i-2], prev1 = dp[i-1]
    prev2, prev1 := 1, 1

    for i := 2; i <= n; i++ {
        current := prev1 + prev2
        prev2 = prev1
        prev1 = current
    }

    return prev1
}
```
