# 53. 简化路径

## 题目描述

给你一个字符串 `path`，表示指向某一文件或目录的 Unix 风格 **绝对路径**（以 `'/'` 开头），请你将其转化为更加简洁的规范路径。

在 Unix 风格的文件系统中规则如下：
- 一个点 `'.'` 表示当前目录本身。
- 两个点 `'..'` 表示将目录切换到上一级（指向父目录）。
- 任意多个连续的斜杠（即 `'//'` 或 `'///'`）都被视为单个斜杠 `'/'`。
- 任何其他格式的点（例如 `'...'` 或 `'....'`）均被视为文件/目录名称。

返回的 **规范路径** 必须遵循下述格式：
- 始终以斜杠 `'/'` 开头。
- 两个目录名之间必须只有一个斜杠 `'/'`。
- 最后一个目录名（如果存在）**不能** 以 `'/'` 结尾。
- 路径仅包含从根目录到目标文件或目录的路径上的目录（即不含 `'.'` 或 `'..'`）。

**示例 1：**

```
输入：path = "/home/"
输出："/home"
解释：注意，最后一个目录名后面没有斜杠
```

**示例 2：**

```
输入：path = "/../"
输出："/"
解释：从根目录向上一级是不可行的，因为根目录是你可以到达的最高级
```

**示例 3：**

```
输入：path = "/home//foo/"
输出："/home/foo"
解释：在规范路径中，多个连续斜杠需要替换为一个斜杠
```

**示例 4：**

```
输入：path = "/a/./b/../../c/"
输出："/c"
```

**约束条件：**

- `1 <= path.length <= 3000`
- `path` 由英文字母、数字、`'.'`、`'/'` 或 `'_'` 组成
- `path` 是一个有效的 Unix 风格绝对路径

## 题目分析

### 算法思路

**核心思路：** 规范路径其实就是「把所有斜杠折叠成一个、去掉 `.`、用 `..` 回退一级」之后得到的结果。回过头看：`.` 是无操作，多个连续 `/` 等价于一个 `/`，只有 `..` 才真正影响结果，而且它的作用是**抵消掉前面最近的一个目录名**——又是「最近出现的最先被消掉」，符合后进先出，所以用栈。

**算法步骤：**

1. 用 `strings.Split(path, "/")` 把路径按 `/` 切开。这样 `""`（来自开头、结尾或连续的斜杠）、`"."`、`".."` 都会成为独立的字符串片段。
2. 遍历每个片段：
   - `part == ""` 或 `part == "."`：忽略（前者是多余的斜杠，后者是当前目录）。
   - `part == ".."`：说明要回退一级。若栈非空，弹出栈顶；若栈为空，说明已经在根目录，根目录的上级仍是根目录，直接忽略。
   - 其它情况：这是一个真实目录名（包括 `"..."`、`"...."` 这类「多于两个点的字符串」，题目规定它们按普通名字处理），压入栈。
3. 用 `strings.Join(stack, "/")` 把栈中目录名连接，并在最前面补一个 `"/"`，即 `"/" + strings.Join(stack, "/")`。栈为空时 `Join` 返回空串，结果正好是 `"/"`。

**为什么正确：** 维护不变量——**处理完前 `k` 个片段后，栈中自底向上恰好是「把这些片段解析成规范路径后」的目录序列**（即把已处理部分视作一条从根出发的路径，栈就是沿途经过的目录）。

- 空片段和 `.` 不改变路径指向，忽略即可，不变量保持。
- `..` 在栈非空时弹出栈顶，等价于「回到父目录」，正是规范路径中 `..` 的语义；栈为空时无父目录可回，忽略即可，不变量保持。
- 普通目录名追加到路径末尾，压栈即可。

遍历结束后，栈中序列对应的规范路径唯一：规范路径的定义要求「以 `/` 开头、目录名之间只有一个 `/`、不以 `/` 结尾、不含 `.` 和 `..`」，而 `"/" + Join(stack, "/")` 恰好满足全部四条（栈为空时结果是 `"/"`，也没有多余的斜杠）。又因为所有的 `.` 与 `..` 都已被消解，任何合法输入都会被解析成这条唯一的规范路径，所以算法输出正确。

### 复杂度分析

- **时间复杂度**：O(n)。`Split` 扫一遍字符串，遍历片段总数不超过字符数，`Join` 再扫一遍栈中字符；各步都是线性。
- **空间复杂度**：O(n)。`Split` 产生的片段切片与分割出的子串，加上栈，总量与路径长度同阶。

### 易错点 / 边界情况

- **栈为空时遇到 `..` 不能弹**：必须判断 `len(stack) > 0`，否则切片越界 panic。示例 2 的 `/../` 就是这种情况，答案是 `"/"` 而不是出错。
- **只能把恰好等于 `"."` 或 `".."` 的片段当作特殊处理**：`"..."`、`"...."`、`.hidden` 都是合法目录名，必须原样保留。判断用 `part == ".."` 这种整体比较，不要写成 `strings.HasPrefix(part, ".")`。
- **空片段的来源有三种**：开头的 `/`、结尾的 `/`、以及 `//` 产生的中间空段。统一用 `part == ""` 过滤即可，不必特殊处理结尾。
- **根目录的输出是 `"/"` 而不是空串**：`strings.Join(nil, "/")` 返回 `""`，所以必须显式加上前缀 `"/"`。
- **不要在末尾再加斜杠**：`Join` 的结果天生不带尾斜杠，正好满足要求；反过来，如果手工拼接时漏判，很容易写出 `"/home/"`。
- **不要用 `filepath.Clean` 代替**：一是它的语义依赖操作系统（Windows 上分隔符是 `\`），二是它不保证「任意多连续斜杠折叠成单个」在各种平台上的行为一致；手写逻辑更可控。
- **路径可能只有根目录**：`path = "/"` 时 `Split` 得到 `["", ""]`，两个片段都被忽略，栈为空，返回 `"/"`。
- **不要修改原字符串**：`Split` 返回的子串与原始字符串共享底层数组，但这里只读不写，是安全的。

## Go 代码实现

```go
import "strings"

func simplifyPath(path string) string {
    // 按 '/' 分割路径
    parts := strings.Split(path, "/")
    var stack []string

    for _, part := range parts {
        // 忽略空字符串（连续斜杠）和当前目录 "."
        if part == "" || part == "." {
            continue
        }
        // 返回上级目录：弹出栈顶
        if part == ".." {
            if len(stack) > 0 {
                stack = stack[:len(stack)-1]
            }
        } else {
            // 有效目录名，压入栈
            stack = append(stack, part)
        }
    }

    // 用 '/' 连接所有目录
    return "/" + strings.Join(stack, "/")
}
```
