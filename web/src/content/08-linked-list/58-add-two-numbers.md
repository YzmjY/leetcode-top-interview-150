# 58. 两数相加

## 题目描述

给你两个 **非空** 的链表，表示两个非负的整数。它们每位数字都是按照 **逆序** 的方式存储的，并且每个节点只能存储 **一位** 数字。

请你将两个数相加，并以相同形式返回一个表示和的链表。

你可以假设除了数字 0 之外，这两个数都不会以 0 开头。

**示例 1：**

```
输入：l1 = [2,4,3], l2 = [5,6,4]
输出：[7,0,8]
解释：342 + 465 = 807
```

**示例 2：**

```
输入：l1 = [0], l2 = [0]
输出：[0]
```

**示例 3：**

```
输入：l1 = [9,9,9,9,9,9,9], l2 = [9,9,9,9]
输出：[8,9,9,9,0,0,0,1]
```

**约束条件：**

- 每个链表中的节点数在范围 `[1, 100]` 内
- `0 <= Node.val <= 9`
- 题目数据保证列表表示的数字不含前导零

## 题目分析

### 算法思路

**核心思路：** 这就是小学竖式加法。竖式加法从**最低位**开始逐位相加，逢十进一。本题的两个链表恰好是**逆序**存储的（表头就是最低位），所以顺着链表从头往后走，正好就是竖式里从个位往高位走的方向，**完全不需要反转链表**。

唯一需要额外携带的信息是「进位」`carry`。每读一位，把两个链表当前位的数字（某条链已经走完就按 0 算）与 `carry` 相加，`sum % 10` 就是结果的这一位，`sum / 10` 就是新的进位。

由于结果的表头是动态产生的，用一个 **dummy（哑节点）** 作为结果链表的哨兵，`cur` 指向结果链的末尾，每次把新节点接在 `cur.Next` 上，最后返回 `dummy.Next`，这样就避免了「结果第一个节点」的特殊处理。

**算法步骤：**

1. `dummy := &ListNode{}`，`cur := dummy`，`carry := 0`。
2. 循环条件：**只要 `l1 != nil` 或 `l2 != nil` 或 `carry > 0` 就继续**。三个条件缺一不可。
3. 每轮：
   - `sum := carry`；
   - 若 `l1 != nil`，把 `l1.Val` 加进 `sum` 并让 `l1 = l1.Next`；
   - 若 `l2 != nil`，把 `l2.Val` 加进 `sum` 并让 `l2 = l2.Next`；
   - 新建节点 `cur.Next = &ListNode{Val: sum % 10}`，`cur = cur.Next`；
   - `carry = sum / 10`。
4. 循环结束，返回 `dummy.Next`。

**为什么正确：** 维护不变量——**每轮结束后，`dummy.Next` 起这条已构造的链恰好表示「两个加数已经处理过的低位部分之和」，位数与已处理位数相同（低位在前），且 `carry` 是把这部分之和向更高位产生的进位。**

- 初始状态：已处理 0 位，和为 0，`carry = 0`，不变量成立。
- 归纳步：设两个加数已处理部分的当前位分别是 `v1`、`v2`（对应链表走出该位，走完则视作 0），那么「已处理部分 + 当前位」之和等于 `v1 + v2 + carry`。它的个位数字就是结果链的当前位（`sum % 10`），而产生的进位就是 `sum / 10`——因为 `v1, v2 <= 9` 且 `carry <= 1`，所以 `sum <= 19`，`sum / 10` 只能是 0 或 1，恰好是「逢十进一」的正确进位。把它追加到结果链后，不变量保持。
- 终止：循环在「两条链都走完、且没有进位」时退出，说明两个数的所有位都已处理，且最高位没有溢出。此时结果链就是完整的和。
- 循环条件里的 `carry > 0` 专门处理最后一位产生的进位。示例 3 的 `9999999 + 9999` 最高位相加后仍留有一个进位 1，必须再补一个值为 1 的节点，结果才会是 8 位数。

### 复杂度分析

- **时间复杂度**：O(max(n, m))，n、m 为两个链表的长度。每位只处理一次；若最高位有进位，还会多跑一轮（因此严格说是 O(max(n, m) + 1)，同阶）。
- **空间复杂度**：O(max(n, m))，结果链表的节点数（若把结果本身也算入）。除此之外只用了 `dummy`、`cur`、`carry` 等常数个变量。

### 易错点 / 边界情况

- **循环条件不能只写 `l1 != nil || l2 != nil`**：必须加上 `|| carry > 0`，否则最高位的进位会丢失。例如 `[9,9,9] + [1]` 会错误地返回 `[0,0,0]` 而不是 `[0,0,0,1]`。
- **取值前必须判空**：两条链表长度不同，较短的会先走完，直接写 `l1.Val` 会 panic。正确写法是「如果非空就取值并前移，否则当作 0」。
- **某条链走完后不能提前跳出循环**：剩下的那条链还要继续和 `carry` 相加。用统一的 `sum` 累积方式写，就自然处理了长度不等的情况。
- **新节点必须新建**：`cur.Next` 应该是 `&ListNode{...}`，不能复用输入节点（输入节点的值会被覆盖，且多条链会互相干扰）。
- **返回 `dummy.Next` 而不是 `dummy`**：哑节点本身不在结果里；如果两条链都是 0，结果是单个值为 0 的节点（示例 2），`dummy.Next` 恰好指向它。
- **不要试图把链表还原成整数再相加**：节点数可达 100 位，远超任何整型；逐位模拟才是正解。
- **不要反转输入链表**：逆序存储恰好与竖式方向一致，反转反而是多余操作，还会破坏输入。
- **加法不会溢出**：每位最大 9，加上进位最大 19，用 `int` 完全安全。
- **输入保证「除 0 以外无前导零」**：这是指原数没有前导零（即链表末尾没有多余的 0）；但结果链表允许出现 0，例如 `5 + 5 = 10` 对应 `[0,1]`。

## Go 代码实现

```go
// ListNode 链表节点定义
type ListNode struct {
    Val  int
    Next *ListNode
}

func addTwoNumbers(l1 *ListNode, l2 *ListNode) *ListNode {
    // Dummy 节点，简化结果链表的构建
    dummy := &ListNode{}
    cur := dummy
    carry := 0 // 进位

    // 只要还有节点或进位未处理完，就继续循环
    for l1 != nil || l2 != nil || carry > 0 {
        sum := carry

        if l1 != nil {
            sum += l1.Val
            l1 = l1.Next
        }
        if l2 != nil {
            sum += l2.Val
            l2 = l2.Next
        }

        // 当前位的值 = sum % 10
        cur.Next = &ListNode{Val: sum % 10}
        cur = cur.Next

        // 进位 = sum / 10
        carry = sum / 10
    }

    return dummy.Next
}
```
