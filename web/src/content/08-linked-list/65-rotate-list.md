# 65. 旋转链表

## 题目描述

给你一个链表的头节点 `head`，旋转链表，将链表每个节点向右移动 `k` 个位置。

**示例 1：**

```
输入：head = [1,2,3,4,5], k = 2
输出：[4,5,1,2,3]
```

**示例 2：**

```
输入：head = [0,1,2], k = 4
输出：[2,0,1]
```

**约束条件：**

- 链表中节点的数目在范围 `[0, 500]` 内
- `-100 <= Node.val <= 100`
- `0 <= k <= 2 * 10^9`

## 题目分析

### 算法思路

**核心思路：** 最直白的做法是「每次把尾节点摘下来放到头部，重复 k 次」。但 `k` 可以到 `2 * 10^9`，这个循环不可接受。

关键观察有两条：

1. **右移 n 位等于没动**（每个节点都回到原位），所以真正需要移动的步数是 `k mod n`。取模后 `k < n`，规模与链表长度同阶。
2. **右移 k 位，就是把链表末尾的 k 个节点整体搬到前面**。设链表为 `A`（前 n-k 个节点）+ `B`（后 k 个节点），右移后的结果就是 `B + A`。

要让一段后缀整体跑到前面，最优雅的做法是**先首尾相连成环，再从正确的位置剪断**：环上每个节点都能顺着 `Next` 走到任意位置，从「新尾节点」处剪开就得到了旋转后的链表。

**算法步骤：**

1. **特判**：`head == nil`、`head.Next == nil`（只有一个节点，怎么转都一样）或 `k == 0`，直接返回 `head`。
2. **求长度并定位尾节点**：从 `head` 出发一路走到最后一个节点，同时数出长度 `n`，循环结束时 `tail` 指向原尾节点。
3. **取模**：`k = k % n`。若此时 `k == 0`，说明旋转的是整数圈，链表不变，直接返回 `head`。**这一步要在成环之前完成**，否则链表会带着环被返回。
4. **成环**：`tail.Next = head`。
5. **找新尾节点**：结果是 `B + A`，其中 `A` 有 `n - k` 个节点，所以新尾节点是原来正数第 `n - k` 个节点。从 `head` 出发走 `n - k - 1` 步即可到达它。
6. **断开环**：`newHead := newTail.Next`；把 `newTail.Next` 置为 `nil`，环就断开了，`newHead` 就是新头节点。
7. 返回 `newHead`。

**为什么正确：**

- **取模的合理性**：整条链表长度是 `n`，连续右移 `n` 次会让每个节点恰好回到原来的位置，所以右移 `k` 位与右移 `k mod n` 位得到完全相同的链表。这一步把问题规模从 O(k) 降到 O(n)。
- **断点位置**：把原链写成 `A`（前 n-k 个节点）+ `B`（后 k 个节点）。成环后，`A` 的最后一个节点（正数第 `n-k` 个）的后继正是 `B` 的第一个节点。从它后面剪开，读出来的顺序就是 `B` 接 `A`——即原来的后缀整体移到了前面，正是「右移 k 位」的定义（每个节点向后挪了 k 个位置，末尾的 k 个溢出到开头）。
- **`newTail` 的定位**：正数第 `n-k` 个节点从 `head` 数起，需要走 `n-k-1` 步（第 1 个节点不用走）。因为 `1 <= k <= n-1`（取模后且非 0），所以 `n-k-1 >= 0`，这个范围合法，不会越界。

**关键理解**：

- 向右旋转 k 次 = 倒数第 k 个节点成为新头节点（模 n 后）。
- 因此新尾节点是倒数第 k+1 个节点，即正数第 n - k 个节点。

### 复杂度分析

- **时间复杂度**：O(n)。第一次遍历求长度 O(n)，第二次遍历找新尾节点 O(n-k) <= O(n)，其余都是常数操作。与 `k` 的大小无关。
- **空间复杂度**：O(1)，只使用了 `tail`、`newTail`、`newHead` 等常数个指针。

### 易错点 / 边界情况

- **先取模、再成环**：如果先把尾部接上头部形成环，再去判断 `k % n == 0`，直接返回就会返回一条**带环的链表**，评测时会出现死循环或结果错误。代码的顺序是「求长度 → 取模 → 判断 0 → 成环」，务必保持。
- **`k % n == 0` 要直接返回**：除了上面说的成环问题，这是因为旋转整数圈后链表完全不变，不必做任何指针操作。
- **单节点链表的特判并非必需**：`head.Next == nil` 时 `n = 1`，`k % 1` 恒为 0，会立即走「直接返回」分支。代码里保留这个特判只是让「怎么转都一样」的意图更清楚，删掉也不会算错。
- **走 `n-k-1` 步，不是 `n-k` 步**：`newTail` 是第 `n-k` 个节点，从第 1 个节点出发只需走 `n-k-1` 次。多走一步会把断点移到 `B` 中间，结果整体错位。
- **`k` 的取模必须用 `k % n` 而不是 `k - n`**：`k` 可以远大于 `n`（上限 `2 * 10^9`）。
- **最后要返回 `newHead` 而不是 `head`**：旋转后头节点已经变了；`head` 通常落在链表中间。
- **不要把 `newTail.Next` 置 nil 之前就返回**：忘了断环会得到带环的链表。
- **空链表**：约束允许 `head == nil`（节点数可以为 0），特判直接返回即可。
- **不要用「逐次搬移尾节点」的循环**：时间复杂度会是 O(n·k)，在 `k` 很大时超时。

## Go 代码实现

```go
// ListNode 链表节点定义
type ListNode struct {
    Val  int
    Next *ListNode
}

func rotateRight(head *ListNode, k int) *ListNode {
    // 特殊情况：空链表、单节点、k = 0
    if head == nil || head.Next == nil || k == 0 {
        return head
    }

    // 计算链表长度，同时定位尾节点
    tail := head
    n := 1
    for tail.Next != nil {
        tail = tail.Next
        n++
    }

    // 实际需要旋转的步数
    k = k % n
    if k == 0 {
        return head
    }

    // 形成环
    tail.Next = head

    // 找到新尾节点（倒数第 k+1 个，正数第 n-k 个）
    newTail := head
    for i := 0; i < n-k-1; i++ {
        newTail = newTail.Next
    }

    // 断开环：新头节点 = 新尾节点的 Next
    newHead := newTail.Next
    newTail.Next = nil

    return newHead
}
```
