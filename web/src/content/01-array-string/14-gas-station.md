# 14. 加油站

## 题目描述

在一条环路上有 `n` 个加油站，其中第 `i` 个加油站有汽油 `gas[i]` 升。

你有一辆油箱容量无限的汽车，从第 `i` 个加油站开往第 `i+1` 个加油站需要消耗汽油 `cost[i]` 升。你从其中的一个加油站出发，开始时油箱为空。

给定两个整数数组 `gas` 和 `cost`，如果你可以按顺序绕环路行驶一周，则返回出发时加油站的编号，否则返回 `-1`。如果存在解，则 **保证** 它是 **唯一** 的。

**示例 1：**

```
输入: gas = [1,2,3,4,5], cost = [3,4,5,1,2]
输出: 3
解释:
从 3 号加油站(索引为 3 处)出发，可获得 4 升汽油。此时油箱有 = 0 + 4 = 4 升汽油
开往 4 号加油站，此时油箱有 4 - 1 + 5 = 8 升汽油
开往 0 号加油站，此时油箱有 8 - 2 + 1 = 7 升汽油
开往 1 号加油站，此时油箱有 7 - 3 + 2 = 6 升汽油
开往 2 号加油站，此时油箱有 6 - 4 + 3 = 5 升汽油
开往 3 号加油站，你需要消耗 5 升汽油，正好足够你返回到 3 号加油站。
因此，3 可为起始索引。
```

**示例 2：**

```
输入: gas = [2,3,4], cost = [3,4,3]
输出: -1
解释:
你不能从 0 号或 1 号加油站出发，因为没有足够的汽油可以让你行驶到下一个加油站。
我们从 2 号加油站出发，可以获得 4 升汽油。此时油箱有 = 0 + 4 = 4 升汽油
开往 0 号加油站，此时油箱有 4 - 3 + 2 = 3 升汽油
开往 1 号加油站，此时油箱有 3 - 3 + 3 = 3 升汽油
你无法返回 2 号加油站，因为返程需要消耗 4 升汽油，但是你的油箱只有 3 升汽油。
因此，无论怎样，你都不可能绕环路行驶一周。
```

**约束条件：**

- `n == gas.length == cost.length`
- `1 <= n <= 10^5`
- `0 <= gas[i], cost[i] <= 10^4`

## 题目分析

**算法思路：** 朴素做法是从每个加油站出发都模拟绕行一圈，最坏 O(n²)。先看一个必要条件：记每站净收益 `net[i] = gas[i] - cost[i]`，绕行一周的总净收益必须非负，即 `sum(net) >= 0`，否则直接返回 -1。再抓住关键观察：如果从 A 出发，走到 B 时油箱首次变为负数，那么 A 和 B 之间的任何加油站 C 都无法作为起点开到 B——从 A 出发到达 C 时油箱非负，而从 C 出发相当于丢掉这段非负的积累，之后只会更少。于是这一整段起点可以一次性排除，只需从 `B+1` 重新尝试，整体扫描一遍即可。

**算法步骤：**

1. 先统计 `totalGas` 与 `totalCost`，若 `totalGas < totalCost` 直接返回 -1。
2. 令起点 `start = 0`、油箱 `tank = 0`，从左到右遍历 `i = 0..n-1`：`tank += gas[i] - cost[i]`；若 `tank < 0`，说明从当前 `start` 出发到不了 `i+1`，于是令 `start = i + 1`、`tank = 0`（新起点按空箱重新计油）。
3. 遍历结束后返回 `start`。

**为什么正确：**

- **中间站点可以一次性排除：** 设从 A 出发第一次在 B 处 `tank < 0`，记前缀和 `S(A,B) < 0`，而对所有 `A <= k < B` 有 `S(A,k) >= 0`。对任意 `A < C <= B`，从 C 出发到 B 的累计净收益为 `S(C,B) = S(A,B) - S(A,C-1)`。由于 `S(A,C-1) >= 0`，得 `S(C,B) <= S(A,B) < 0`，即 C 同样到不了 B。因此把起点直接跳到 `B+1` 不会漏掉任何可行解。
- **最后返回的 `start` 一定可行：** 设最后一次重置发生在下标 `s-1`（即 `start = s`）。重置之后油量再未变负，所以 `S(s,k) >= 0` 对 `k = s..n-1` 成立；并且每次重置都意味着前缀和走到新的最低点，故 `s-1` 是 `S(0,·)` 在 `[0, s-1]` 上的最小值，即 `S(k+1, s-1) <= 0`。于是环路上接续前行到下标 `k`（`0 <= k <= s-1`）时的油量为 `sum(net) - S(k+1, s-1) >= sum(net) >= 0`，绕回起点前始终不会断油。综合两点，返回的起点正确。

**时间复杂度：** O(n)，两次线性扫描（两次也可以合并成一次，分开写更清晰）。

**空间复杂度：** O(1)，只用常数个变量。

**易错点：**

- 必须先判断 `totalGas < totalCost` 再做贪心。少了这个前置判断，无解时也会返回一个看似合法的下标。
- 重置时起点是 `start = i + 1`（不是 `i`），且 `tank` 必须清零——新起点的油箱按空箱开始计算。
- 题目保证有解时起点唯一，但给定的数组本身可能有多解；本算法返回的是最靠前的可行起点（上面的推导保证它一定可行）。
- 边界：`n == 1` 时 `gas[0] >= cost[0]` 返回 0，否则返回 -1；`cost[i] == 0` 时该段只进不出，不影响正确性。
- 油量会累加到较大数值（`gas[i]` 最大 10⁴），但总量有限，用 `int` 足够。

## Go 代码实现

```go
// canCompleteCircuit 找到可以绕环路行驶一周的起始加油站编号
// 贪心策略：如果从某站出发到不了下一站，则中间的站作为起点也不行
func canCompleteCircuit(gas []int, cost []int) int {
    n := len(gas)
    // totalGas 和 totalCost 用于判断是否存在解
    totalGas, totalCost := 0, 0
    for i := 0; i < n; i++ {
        totalGas += gas[i]
        totalCost += cost[i]
    }
    // 总汽油量小于总消耗量，不可能完成环路
    if totalGas < totalCost {
        return -1
    }

    // start 记录当前尝试的起点
    // tank 记录当前油箱中的汽油量
    start := 0
    tank := 0

    for i := 0; i < n; i++ {
        // 从当前加油站出发：加油，消耗到下一站
        tank += gas[i] - cost[i]
        // 如果油箱为负，说明从当前起点无法到达 i+1
        if tank < 0 {
            // 尝试从下一个加油站重新出发
            start = i + 1
            tank = 0
        }
    }

    return start
}
```
