# 143. 最小路径和 (Minimum Path Sum)

## 题目描述

给定一个包含非负整数的 `m x n` 网格 `grid`，请找出一条从左上角到右下角的路径，使得路径上的数字总和为最小。

**说明：** 每次只能向下或者向右移动一步。

**示例 1：**

```
输入：grid = [[1,3,1],[1,5,1],[4,2,1]]
输出：7
解释：因为路径 1->3->1->1->1 的总和最小。
```

**示例 2：**

```
输入：grid = [[1,2,3],[4,5,6]]
输出：12
```

**约束条件：**

- `m == grid.length`
- `n == grid[i].length`
- `1 <= m, n <= 200`
- `0 <= grid[i][j] <= 200`

## 题目分析

### 算法思路

**关键观察。** 每一步只能向右或向下，于是到达 `(i, j)` 的最后一步只有两种可能：从上方 `(i-1, j)` 下来，
或从左方 `(i, j-1)` 过来。也就是说，「走到 `(i, j)` 的最小代价」只依赖于左上角到这两个邻居的最小代价，
而与具体经过了哪些格子无关（无后效性）。再加上只能向右/向下意味着移动方向是单调的，
格子之间存在天然的拓扑序：按行、列递增的顺序计算，用到的上方/左方一定已经算完。

- **状态定义**：`dp[i][j]` = 从左上角 `(0, 0)` 走到 `(i, j)` 的最小路径和（包含两端格子的值）。
- **状态转移**：`dp[i][j] = grid[i][j] + min(dp[i-1][j], dp[i][j-1])`。
- **边界条件**：
  - `dp[0][0] = grid[0][0]`；
  - 第一行没有上方：`dp[0][j] = dp[0][j-1] + grid[0][j]`（只能一直向右）；
  - 第一列没有左方：`dp[i][0] = dp[i-1][0] + grid[i][0]`（只能一直向下）。

**为什么正确。** 任取一条从 `(0,0)` 到 `(i,j)` 的路径，按最后一步的方向分成「最后一步从上方来」和
「最后一步从左方来」两类：两类互不重复，且覆盖所有路径。去掉最后一步后，前一类的前缀是一条以
`(i-1,j)` 为终点的路径，后一类的前缀以 `(i,j-1)` 为终点。要让总和最小，前缀也必须取对应子问题的最小值
（否则把前缀换成更优的会得到更小的总和），所以候选值恰好是 `dp[i-1][j] + grid[i][j]` 与
`dp[i][j-1] + grid[i][j]`，取较小者即为 `dp[i][j]` 的最优值。对格子按行列递增顺序递推，
每个子问题在被使用前都已计算完成，归纳可得最终 `dp[m-1][n-1]` 就是答案。

**空间优化（一维滚动数组）。** `dp[i][j]` 只依赖上方和左方，可以用长度为 `n` 的一维数组滚动：
从左到右更新时，覆盖前的 `dp[j]` 就是「上方」`dp[i-1][j]`，而 `dp[j-1]` 已经是本行的「左方」`dp[i][j-1]`：

```
dp[j] = grid[i][j] + min(dp[j], dp[j-1])    // j = 0 时无左方，dp[0] += grid[i][0]
```

**本例代码：直接原地修改 `grid`。** 由于递推完 `(i, j)` 后不再需要它原来的值，
Go 实现直接把结果写回 `grid[i][j]`，相当于用输入数组当 DP 表：

- `i == 0 && j == 0`：跳过（起点值不变）；
- `i == 0`：`grid[0][j] += grid[0][j-1]`；
- `j == 0`：`grid[i][0] += grid[i-1][0]`；
- 其余：`grid[i][j] += min(grid[i-1][j], grid[i][j-1])`。

这样额外空间降为 O(1)，但**会改动调用方传入的数组**，如果需要保留输入，应先复制一份。

### 复杂度分析

- **时间复杂度**：O(m·n)。每个格子做一次常数时间的比较与加法，m, n ≤ 200 时最多 4×10⁴ 个格子。
- **空间复杂度**：O(1)（代码原地修改 `grid`）。若不修改输入，则用一维滚动数组是 O(n)，
  完整 DP 表是 O(m·n)。
- 答案量级：格子数 ≤ 4×10⁴、每格 ≤ 200，路径和 ≤ 8×10⁶，`int` 足够，不会溢出。

### 关键点

- 按「从上到下、从左到右」的拓扑序填表，保证用到的上方/左方值已经就绪；反过来写会读到旧值出错。
- 第一行、第一列没有选择余地，必须单独处理，否则会越界或错误地取到 `min` 的默认值。
- 原地修改是本题代码的取舍：空间最优，但有副作用（LeetCode 判题不检查输入是否被改动）。
- 本题与「不同路径 II」共用同一个递推骨架，区别只在求和还是计数、以及障碍物如何归零。

## Go 代码实现

```go
package main

func minPathSum(grid [][]int) int {
    m, n := len(grid), len(grid[0])

    // 可以直接在原数组上修改，节省空间
    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if i == 0 && j == 0 {
                continue // 起点不变
            } else if i == 0 {
                // 第一行：只能从左来
                grid[i][j] += grid[i][j-1]
            } else if j == 0 {
                // 第一列：只能从上来
                grid[i][j] += grid[i-1][j]
            } else {
                // 取上方和左方的最小值
                if grid[i-1][j] < grid[i][j-1] {
                    grid[i][j] += grid[i-1][j]
                } else {
                    grid[i][j] += grid[i][j-1]
                }
            }
        }
    }

    return grid[m-1][n-1]
}
```
