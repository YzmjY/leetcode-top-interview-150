# 可视化演示精修方案（Native Demo 迁移计划)

> **读者**:接手演示精修工作的前端开发者
> **目标**:把 150 题中「自动迁移版」演示逐题升级为手写 React 组件,达到题 28「盛最多水的容器」的品质水准,并保证 150 题视觉风格完全统一
> **预估工作量**:模式库建设约 3–5 天;之后每题 1–3 小时;全部完成约 4–6 周(单人)

---

## 0. 一句话现状

每道题的演示由三层组成:**步骤数据 → 舞台渲染 → 外壳交互**。目前只有题 28 三层全是手写的;其余 149 题复用了旧站的步骤数据和渲染函数(质量良好),但套着全新的 React 外壳。**本方案只动中间一层(舞台渲染),外层的 DemoShell 外壳不许改。**

### 1.2 渲染决策链

`ProblemPage` → `VizSlot(num)`(`src/demo/registry.tsx`)→ 查 `native` 注册表:

- **命中** → 懒加载手写 React 组件(精修版)

## 2. 设计规范(风格一致性的来源)

### 2.1 色彩令牌(必须使用 CSS 变量,禁止硬编码色值)

所有颜色写在 `src/index.css` 的 `:root` / `.dark` 里,演示组件**只允许引用变量**,这样暗色模式自动生效。

| 变量 | 用途 | 亮色 | 暗色 |
|---|---|---|---|
| `hsl(var(--amber))` | **主强调色**:当前关注元素、左指针、主高亮 | 琥珀 | 亮琥珀 |
| `hsl(var(--teal))` | **次强调色**:右指针、对照元素 | 青绿 | 亮青绿 |
| `hsl(var(--water))` | **填充/区域色**:水量、区间覆盖 | 蓝 | 蓝 |
| `hsl(var(--ink))` | 主文字、实体元素 | 墨色 | 暖白 |
| `hsl(var(--ink-soft))` | 次要文字、说明 | 灰 | 灰 |
| `hsl(var(--paper))` | 舞台底色 | 暖纸 | 深墨 |
| `hsl(var(--card))` | 卡片底 | 白 | 深灰蓝 |
| `hsl(var(--border))` | 描边 | 浅褐灰 | 深灰 |
| `hsl(var(--easy/medium/hard))` | 语义色:正确/待定/冲突(兼作难度色) | 绿/橙/红 | 同 |
| `hsl(var(--easy-soft))` 等 `*-soft` | 对应的浅底色,用于徽章、高亮底 | — | — |

**语义色使用约定**(与迁移版 legacy.css 保持一致,用户已建立认知):

- 🟠 amber = 当前正在处理 / 主指针
- 🟢 teal = 对照指针 / 辅助结构
- 🟢 easy 绿 = 已确定、正确、命中
- 🟡 medium 橙 = 待定、候选、警告
- 🔴 hard 红 = 冲突、丢弃、非法
- 🔵 water 蓝 = 区域填充、累积量
- 灰 + 透明度 0.1–0.3 = 已排除 / 未处理

### 2.2 字体与数字

- 数值、下标、代码一律用 `font-code`(JetBrains Mono 栈):`className="font-code"`
- SVG `<text>` 中数字同样加 `className="font-code"`
- 标题/大字用 `font-display`(衬线栈),演示内部一般用不到
- 正文字号:舞台内 12–15px,解说 13px,标签 11–12px

### 2.3 圆角、描边、阴影

- 单元格/柱子圆角 5–8px,卡片 10–12px
- 描边 1.5–2px,颜色 `hsl(var(--border))`
- 亮色主题下实体元素允许 `box-shadow: 0 1px 2px hsl(230 25% 13% / 0.05)`;暗色主题下省略
- 当前关注元素可加 `box-shadow: 0 4px 10px hsl(28 92% 45% / 0.25)`(琥珀光晕)

### 2.4 间距与布局

- 舞台内边距由 DemoShell 统一提供(`px-4 py-5 sm:px-6`),组件内部不再加外壳
- 舞台内容垂直间距 12–16px(`gap-3` / `gap-4`)
- 舞台默认水平居中;图表类 SVG 用 `viewBox` + `className="w-full"` 自适应宽度

## 3. 演示组件契约

### 3.1 DemoShell  Props(`src/demo/DemoShell.tsx`)

外壳已实现的,**组件不用管**:步骤徽章、上一步/下一步/重置/跳到最后/自动播放、可点击分段进度条、图例行、键盘快捷键(←/→ 步进,空格播放暂停)、焦点环。

```ts
interface DemoShellProps<T> {
  title: string                       // 演示标题,如 "双指针收敛过程"
  info?: string | ((step, i) => string) // 数据说明条(输入数据展示)
  steps: T[]                          // ★ 步骤数据
  renderStep: (step: T, index: number) => ReactNode  // ★ 舞台渲染
  describe: (step: T, index: number) => string       // ★ 每步解说
  legend?: { color: string; label: string }[]        // 图例(3–5 项)
  autoMs?: number                     // 自动播放间隔,默认 1100ms
  stageMinHeight?: number             // 舞台最小高度 px
}
```

### 3.2 组件文件标准结构(照抄题 28 的骨架)

```tsx
// src/demo/demos/XxxYyy.tsx
import { useMemo } from 'react'
import { DemoShell } from '../DemoShell'

const INPUT = [/* 固定的示例输入,与题解 markdown 中示例一致 */]

interface Step {
  // 这一步需要的全部状态(指针位置、数组快照、当前值、阶段标记…)
  phase: 'init' | 'step' | 'done'
  note: string
}

function buildSteps(): Step[] {
  // 用真实算法跑一遍输入,每轮 push 一个不可变快照
  // 必须包含:init(初始状态讲解)、中间每步、done(结论陈述)
}

function Stage(step: Step) {
  // 纯函数渲染:同一个 step 任何时候渲染结果一致
  // 不要在这里改状态、不要定时器
}

export default function XxxDemo() {
  const steps = useMemo(buildSteps, [])
  return (
    <DemoShell
      title="…"
      info={`…`}
      steps={steps}
      renderStep={(s) => <Stage {...s} />}
      describe={(s) => s.note}
      legend={[...]}
    />
  )
}
```

然后在 `registry.tsx` 的 `native` 表登记:

```ts
const native = {
  28: () => import('./demos/ContainerWithMostWater'),
  16: () => import('./demos/TrappingRainWater'),   // 新增
}
```

最后把 ProblemPage 的「新版交互」徽章自动点亮(已有逻辑,无需改)。

### 3.3 步骤数据规范

1. **第一步永远是 `init`**:讲输入是什么、变量怎么初始化、不变量是什么
2. **最后一步永远是 `done`**:给出最终答案、答案怎么读出来、复杂度一句话
3. 中间每步的 `note` 遵循句式:**「观察 → 判断 → 动作 → 为什么」**,2–4 句,例:

   > 当前容器:宽 8 × 高 min(1, 7) = 1,水量 = 8,未超过历史最大 49。左板(高 1)是短板——移动长板只会让宽度变小且高度不可能超过短板,水量必然不增,因此排除短板,left 右移。

4. 步骤数控制在 **5–40 步**:输入规模以「能看清每一步」为准,不要用题解里的最大示例
5. 每步快照不可变(`arr.slice()`),禁止在渲染期改 steps 里的数据

### 3.4 迁移素材的来源

每题的旧脚本在 `web/src/demo/legacy/gen/<NN>-<slug>.js`(由 `docs/assets/interactive/` 自动生成)。**旧脚本里的 `buildSteps` 逻辑和解说文案可以直接搬进新组件**,只需把命令式 DOM 渲染(`Demo.el(...)`)换成 JSX/SVG。解说文案如需精简可以改,但算法事实不许编造——以 `docs/` 中该题 markdown 的分析为准。

## 4. 可视化模式库(先建模式,再批量套用)

精修不是 150 种设计,而是 **8 种模式 × 150 道题**。先做 P0 的 10 个样板题把模式立住,其余题目套模式。

### 模式 A:数组 + 指针(约 40 题:双指针、快慢指针、滑动窗口、二分)

- 横向单元格行,值在格内,下标在格下,指针标签在格上(三角旗标 + 字母)
- 当前格:琥珀底 + 上浮 3px + 光晕;已排除:灰 + 30% 透明;已确定:绿底
- 参考:题 3(迁移版已有的视觉约定,升级为更精致的间距与动效即可)
- 滑动窗口变体:窗口用半透明琥珀底色块包裹整段区间

### 模式 B:柱状图 + 区域填充(接雨水、股票、直方图类)

- SVG 柱状图,`viewBox` 自适应;柱高线性映射,柱顶标数值
- 累积区域(水量/收益)用 `hsl(var(--water))` 22% 透明度填充 + 顶部虚线描边
- 参考实现:**题 28 `ContainerWithMostWater.tsx`,照它的坐标换算与图层顺序**
- 图层顺序:区域填充 → 柱子 → 指针旗标 → 数值标签 → 基线

### 模式 C:二维网格(矩阵、岛屿、单词搜索、生命游戏)

- 正方形单元格,`display: grid`,gap 6px
- 状态用语义色区分:未访问(白)、当前(琥珀)、已访问(青)、路径/命中(绿)、 obstacle(灰)
- BFS/DFS 扩散步骤用 200ms 内的透明度渐变,禁止整格闪烁
- 坐标标注:仅行列 ≤ 10 时在边缘标行列号

### 模式 D:链表

- 节点为圆角矩形(44px 高),节点间用箭头 `→` 连接;指针标签在节点上方
- 断开/重连的边用过渡:旧边变灰变细,新边琥珀色加粗
- 节点增删用透明度 + 位移,不做弹性动画(避免喧闹)

### 模式 E:树 / 二叉搜索树

- SVG 绘制:节点圆(半径 18–22px),边为直线;按层布局,x 坐标按中序展开
- 当前节点琥珀描边加粗;访问过的 teal 填充;结果路径上的节点绿色
- 树高 > 5 层时只展示局部子树并在底部注明「仅展示以 X 为根的子树」

### 模式 F:图(拓扑、克隆、课程表)

- 节点圆形 + 有向边带箭头(marker-end);布局用手写坐标表(每题输入固定,允许硬编码坐标)
- 入度/状态用节点内小字或外圈颜色环表示
- 不允许使用力导向布局(结果不可复现,违背「每步可复现」原则)

### 模式 G:栈 / 队列 / 堆

- 栈:竖向容器,顶部开口,元素从上方落入(translateY 过渡)
- 队列:横向管道,左进右出
- 堆:用模式 E 的树形展示 + 旁边同步的数组形式(上下双视图)

### 模式 H:DP 表格(一维/二维 DP、Kadane)

- 一维:模式 A 的单元格行 + 每个格子下方显示 `dp[i]` 值,当前格高亮,依赖来源画弧线箭头
- 二维:模式 C 网格,单元格内写 dp 值,当前格与依赖格(上/左/左上)之间用细线连接
- 填表顺序用步骤体现,禁止一次渲染整张表再逐个变色以外的花哨效果

### 各模式的「舞台辅助区」约定

图表下方统一放状态条(参考题 28):2–4 个 `rounded-lg border` 小徽章,显示当前值/最优值/下一步动作;done 步显示绿色「✓ 答案 …」徽章。徽章样式直接复用题 28 的类名组合。

## 5. 动效与交互规范

| 项 | 规范 |
|---|---|
| 属性过渡 | `transition: all 0.35s cubic-bezier(0.34, 1.3, 0.64, 1)`(已有 `.demo-bar` / `.demo-water` 类可复用) |
| 强调脉冲 | 用已有的 `.demo-pulse`(1.4s 呼吸),只用于「最优解/答案」类元素,一屏最多一处 |
| 自动播放 | 默认 1100ms/步;解说超过 80 字的演示可调到 1400ms |
| 步骤切换 | 离散切换,不做插值动画(步进语义优先于流畅感) |
| 禁止事项 | 不自动滚动页面、不播放声音、不用 alert、不用 CSS 动画做无限循环装饰 |

## 6. 响应式与双主题(验收红线)

1. **双主题**:所有颜色走 CSS 变量;交付前必须切换暗色模式肉眼检查一遍(顶栏月亮按钮)
2. **窄屏**:640px 以下单元格缩小(参考 legacy.css 的 media query);SVG 用 viewBox 缩放,不要写死像素宽
3. **触摸**:舞台不依赖 hover 传达关键信息(hover 只能是增强)
4. **键盘**:DemoShell 已获得焦点的快捷键支持,组件内不要再注册全局键盘事件
5. **可访问性**:指针/状态不能只用颜色区分——必须同时有文字标签(如 L/R 旗标)或形状差异

## 7. 每题交付流程(6 步)

```bash
cd web
npm run dev        # 起本地服务
```

1. 读题解:`../docs/<章节目录>/<NN>-<slug>.md`,确认算法与示例
2. 读旧实现:`src/demo/legacy/gen/<NN>-<slug>-demo.js`,搬步骤数据与解说文案
3. 选模式:对照第 4 节确定模式 A–H,找最近的样板题参考
4. 写组件:`src/demo/demos/<Name>.tsx`,按 3.2 的骨架
5. 注册:`src/demo/registry.tsx` 的 `native` 表加一行
6. 自测(见第 8 节清单)后 `npm run build` 必须通过

**不要动**:`DemoShell.tsx`、`legacy/` 目录、`docs/` 内容(发现题解错误单独提 PR 改 docs,不要顺手改)。

## 10. 常见陷阱(血泪清单)

1. **CRLF**:`docs/` 的 markdown 是 CRLF 行尾,解析正则必须兼容 `\r?\n`(content.ts 已踩过)
2. **CSS 类名冲突**:旧舞台类名(`.cell`、`.row`、`.panel`)极其通用,新组件一律用 Tailwind 原子类或带前缀的类名,不要复用裸类名
3. **暗色主题**:调试时记得切暗色看一眼,硬编码浅色在暗色下必翻车
4. **SVG text 颜色**:SVG 内 `fill` 不吃 Tailwind 的 `text-*`,用 `className="fill-[hsl(var(--ink))]"` 或 `fill` 属性配 CSS 变量
5. **不要删 legacy 模块**:它是兜底和素材库;`npm run sync` 会重新生成 `legacy/gen/`,手改会被覆盖
6. **题号即身份**:注册表、文件名、标题里的题号必须与 `mkdocs.yml` 导航一致,站点一切索引按题号走
7. **构建守卫**:提交前跑 `npm run build`,tsc 严格模式会拦住未使用变量等问题;部署由 push 到 master 自动触发,约 1 分钟上线
