# 55. 逆波兰表达式求值

## 题目描述

给你一个字符串数组 `tokens`，表示一个根据 **逆波兰表示法** 表示的算术表达式。

请你计算该表达式。返回一个表示表达式值的整数。

**注意**：
- 有效的运算符为 `'+'`、`'-'`、`'*'` 和 `'/'`。
- 每个操作数（运算对象）都可以是一个整数或者另一个表达式。
- 两个整数之间的除法总是 **向零截断**（即向零取整）。
- 表达式中不含除零运算。
- 输入是一个根据逆波兰表示法表示的算术表达式。
- 答案及所有中间计算结果可以用 **32 位** 整数表示。

**示例 1：**

```
输入：tokens = ["2","1","+","3","*"]
输出：9
解释：该算式转化为常见的中缀算术表达式为：((2 + 1) * 3) = 9
```

**示例 2：**

```
输入：tokens = ["4","13","5","/","+"]
输出：6
解释：该算式转化为常见的中缀算术表达式为：(4 + (13 / 5)) = 6
```

**示例 3：**

```
输入：tokens = ["10","6","9","3","+","-11","*","/","*","17","+","5","+"]
输出：22
解释：
((10 * (6 / ((9 + 3) * -11))) + 17) + 5
= ((10 * (6 / (12 * -11))) + 17) + 5
= ((10 * (6 / -132)) + 17) + 5
= ((10 * 0) + 17) + 5
= (0 + 17) + 5
= 17 + 5
= 22
```

**约束条件：**

- `1 <= tokens.length <= 10^4`
- `tokens[i]` 是一个运算符（`"+"`、`"-"`、`"*"` 或 `"/"`），或是一个在范围 `[-200, 200]` 内的整数

## 题目分析

### 算法思路

**核心思路：** 逆波兰表达式（后缀表达式）的最大特点是不需要括号，也不需要优先级：每个运算符都紧跟在它的两个操作数之后。例如 `2 1 + 3 *`，读到一个 `+` 时，它的两个操作数就是刚刚读过的 `2` 和 `1`——也就是「最近遇到的两个数」。这种「最近的最先用」的结构正是栈：扫到数字就入栈，扫到运算符就取出栈顶两个数算完再压回去。

**算法步骤：**

1. 建一个空栈 `stack`，用来存操作数。
2. 从左到右遍历 `tokens`：
   - 若是运算符 `+`、`-`、`*`、`/`：取出栈顶的两个元素，**较先入栈的记为 `a`（左操作数），后入栈的记为 `b`（右操作数）**，计算 `a op b`，把结果压回栈。
   - 否则是数字：用 `strconv.Atoi` 解析后压栈。
3. 遍历结束，栈中只剩一个元素，就是整个表达式的值，返回 `stack[0]`。

**为什么正确：** 用归纳法。**不变量：处理完前 `k` 个 token 后，栈中从底到顶恰好是「前 `k` 个 token 所构成的表达式」按原顺序化简后剩下的操作数序列。**

- 读到数字 `x`：它本身就是一个不含运算符的子表达式，追加到序列末尾，不变量保持。
- 读到运算符 `op`：在后缀表达式合法的前提下，`op` 作用于它前面**紧邻的两个**子表达式（它们的值分别位于栈顶和栈顶下方）。把它们替换成计算结果，得到的仍是「前 `k` 个 token 化简后的操作数序列」，不变量保持。
- 遍历结束时，整个表达式已经化简为一个操作数，栈中只此一个元素，故返回 `stack[0]` 正确。

操作数的左右顺序在定义上被确定：后缀表达式 `a b -` 的含义是 `a - b`，而 `a` 先入栈、`b` 后入栈，所以 `stack[len(stack)-2]` 是左操作数、`stack[len(stack)-1]` 是右操作数，不能颠倒。

### 复杂度分析

- **时间复杂度**：O(n)，每个 token 只被处理一次，栈操作都是 O(1)。数字解析 `Atoi` 的代价与数字位数成正比，而位数受题面约束（`|值| <= 200`），是常数。
- **空间复杂度**：O(n)，栈最坏情况下存下所有操作数。

### 易错点 / 边界情况

- **减法和除法的左右操作数不能颠倒**：`a := stack[len(stack)-2]`、`b := stack[len(stack)-1]`，结果是 `a - b`、`a / b`。写成 `b - a` 或 `b / a` 在示例 1（`2 1 +`）上看不出来，但 `["3","4","-"]` 会从 `-1` 变成 `1`。
- **除法的舍入方向**：题目要求**向零截断**。Go 的整数除法 `/` 本身就是向零截断的（例如 `7 / -2 == -3`、`-7 / 2 == -3`），所以直接用 `/` 即可；**不要**引入 `math.Floor`（那是向下取整，`-7/2` 会变成 `-4`）。
- **负号与减号的歧义**：`strconv.Atoi("-11")` 能正确解析负数，而 `switch token { case "-": ... }` 是整串精确匹配，`"-11"` 不会命中 `case "-"`。若想用「首字符是 `-`」这类判断来区分运算符，就会把负数误当运算符，务必避免。
- **数字解析的错误处理**：题目保证 token 要么是合法运算符、要么是合法整数，所以 `num, _ := strconv.Atoi(token)` 忽略错误是安全的；不要因为看到了 `_` 就以为这里会吞掉真正的错误。
- **最终结果取 `stack[0]`**：表达式合法时栈中只剩一个元素，写 `stack[0]` 和下溢检查都对；但不能写成 `stack[len(stack)-1]` 之外的花样，也不需要在循环里清理多余元素。
- **运算范围**：题面保证答案与所有中间结果都能用 32 位整数表示，因此 Go 的 `int` 不会溢出。若题目没有这个保证，就需要换成 `int64` 或按题意处理溢出。
- **`tokens` 至少一个元素**（`1 <= tokens.length`），不必考虑空输入；但若题目放宽约束，空输入应单独处理，否则 `stack[0]` 会 panic。

## Go 代码实现

```go
import "strconv"

func evalRPN(tokens []string) int {
    stack := []int{}

    for _, token := range tokens {
        switch token {
        case "+":
            // 弹出两个操作数，相加后压回
            a, b := stack[len(stack)-2], stack[len(stack)-1]
            stack = stack[:len(stack)-2]
            stack = append(stack, a+b)
        case "-":
            // 弹出两个操作数，相减后压回
            a, b := stack[len(stack)-2], stack[len(stack)-1]
            stack = stack[:len(stack)-2]
            stack = append(stack, a-b)
        case "*":
            // 弹出两个操作数，相乘后压回
            a, b := stack[len(stack)-2], stack[len(stack)-1]
            stack = stack[:len(stack)-2]
            stack = append(stack, a*b)
        case "/":
            // 弹出两个操作数，相除后压回（向零截断）
            a, b := stack[len(stack)-2], stack[len(stack)-1]
            stack = stack[:len(stack)-2]
            stack = append(stack, a/b)
        default:
            // 数字：直接解析并压入栈
            num, _ := strconv.Atoi(token)
            stack = append(stack, num)
        }
    }

    return stack[0]
}
```
