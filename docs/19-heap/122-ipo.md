# 122. IPO

## 题目描述

假设力扣（LeetCode）即将开始**IPO**。为了以更高的价格将股票卖给风险投资公司，力扣希望在 IPO 之前开展一些项目以增加其资本。由于资源有限，它只能在 IPO 之前完成最多 `k` 个不同的项目。帮助力扣设计完成最多 `k` 个不同项目后获得最大总资本的方式。

给你 `n` 个项目。对于每个项目 `i`，它都有一个纯利润 `profits[i]`，和启动该项目需要的最小资本 `capital[i]`。

最初，你的资本为 `w`。当你完成一个项目时，你将获得纯利润，且利润将被添加到你的总资本中。

总而言之，从给定项目中选择**最多** `k` 个不同项目的列表，以**最大化最终资本**，并输出最终可获得的最多资本。

答案保证在 32 位有符号整数范围内。

### 示例 1

```
输入：k = 2, w = 0, profits = [1,2,3], capital = [0,1,1]
输出：4
解释：
由于你的初始资本为 0，你仅可以从 0 号项目开始（需要最小资本 0）。
在完成 0 号项目后，你将获得 1 的利润，你的总资本将变为 1。
此时你可以选择开始 1 号或 2 号项目（需要的最小资本都是 1）。
由于你最多可以选择两个项目，所以你需要完成 2 号项目以获得最大的资本。
因此，输出最后最大化的资本，为 0 + 1 + 3 = 4。
```

### 示例 2

```
输入：k = 3, w = 0, profits = [1,2,3], capital = [0,1,2]
输出：6
```

### 约束条件

- `1 <= k <= 10^5`
- `0 <= w <= 10^9`
- `n == profits.length`
- `n == capital.length`
- `1 <= n <= 10^5`
- `0 <= profits[i] <= 10^4`
- `0 <= capital[i] <= 10^9`

## 题目分析

### 算法思路

**朴素想法**：每一轮都在「资本足够启动」的项目里挑利润最大的，执行后再看新解锁了哪些。若每轮都线性扫描全部项目，总复杂度 O(k·n)，在 `n, k` 都到 `10^5` 时不可接受。

**关键观察**：

- 资本只会增加、不会减少，因此**某个项目一旦变得可做，它在之后的所有轮次里都可做**（门槛 `capital[i]` 永远被满足）。
- 把项目按所需资本升序排序后，可以用一个只向前走的指针 `idx`：随着 `w` 变大，把所有新达到门槛的项目「解锁」并放进一个大顶堆（按利润排序）。
- 每轮只需从堆里取堆顶，就得到当前所有可做项目中利润最大者；项目一旦入堆就不会失效（只会在被选中时弹出），堆中最多同时存 `n` 个项目，整体只需 O(n) 空间。

**算法步骤**：

1. 把 `(capital[i], profits[i])` 打包成项目数组，按 `capital` 升序排序。
2. 初始化大顶堆 `h`（按利润比较）与指针 `idx = 0`。
3. 重复至多 `k` 轮：
   - 内层把所有 `projects[idx].capital <= w` 的项目利润入堆并递增 `idx`（每个项目只会入堆一次）；
   - 若堆为空，说明已经没有可执行的项目，提前结束；
   - 否则弹出堆顶（利润最大者），`w += 该利润`，表示完成这个项目。
4. 返回最终的 `w`。

**为什么正确（贪心选择性质 + 交换论证）**：设某一轮中「当前可做集合」里利润最大的项目为 `p*`，贪心解选择它。任取一个最优解，如果它在某一轮选择了一个可做项目 `p != p*`：由于资本单调不减，`p*` 在该轮也一定可做；把解中这一轮的选择换成 `p*` 后，后续任何项目的门槛都不会变得更难满足（资本只会更多），而最终资本的变化量是 `p* - p >= 0`。反复做这样的交换，就能把任意最优解变成贪心解而不降低收益，因此贪心策略最优。

**为什么不直接按利润排序**：可做集合是随 `w` 动态扩张的，堆恰好同时支持「插入新解锁的项目」和「取最大值」两种操作。

### 复杂度分析

- **时间复杂度**：O(n log n + k log n)。
  - 打包与排序：O(n log n)；
  - 每个项目入堆至多一次、出堆至多一次：O(n log n)；
  - 主循环至多 `k` 轮，每轮取出堆顶 O(log n)，共 O(k log n)。
- **空间复杂度**：O(n)，用于排序后的项目数组和堆。

### 关键点

- 使用大顶堆（`Less` 返回 `h[i] > h[j]`）从可执行项目中选择利润最大者。
- 用指针 `idx` 追踪「下一个尚未解锁的项目」，避免重复入堆。
- 当堆为空时说明没有更多可执行项目，提前终止，避免无意义的空转。
- 资本 `w` 会不断累加，注意变量类型要能放下最终结果（题面保证答案在 32 位有符号整数范围内）。
- 项目利润可以为 0，入堆/弹出都正常；只要堆非空，每轮必然弹出一个，不会死循环。

## Go 代码实现

```go
package main

import (
    "container/heap"
    "fmt"
    "sort"
)

// MaxHeap 大顶堆（按利润）
type MaxHeap []int

func (h MaxHeap) Len() int           { return len(h) }
func (h MaxHeap) Less(i, j int) bool { return h[i] > h[j] } // 大顶堆
func (h MaxHeap) Swap(i, j int)      { h[i], h[j] = h[j], h[i] }

func (h *MaxHeap) Push(x any) {
    *h = append(*h, x.(int))
}

func (h *MaxHeap) Pop() any {
    old := *h
    n := len(old)
    x := old[n-1]
    *h = old[:n-1]
    return x
}

func findMaximizedCapital(k int, w int, profits []int, capital []int) int {
    n := len(profits)

    // 将项目打包并按所需资本排序
    type Project struct {
        capital int
        profit  int
    }
    projects := make([]Project, n)
    for i := 0; i < n; i++ {
        projects[i] = Project{capital[i], profits[i]}
    }
    sort.Slice(projects, func(i, j int) bool {
        return projects[i].capital < projects[j].capital
    })

    h := &MaxHeap{}
    heap.Init(h)
    idx := 0 // 当前能入堆的项目的起始索引

    for i := 0; i < k; i++ {
        // 将所有当前资本可启动的项目加入堆
        for idx < n && projects[idx].capital <= w {
            heap.Push(h, projects[idx].profit)
            idx++
        }

        // 如果没有可执行的项目，提前终止
        if h.Len() == 0 {
            break
        }

        // 执行利润最大的项目
        w += heap.Pop(h).(int)
    }

    return w
}

func main() {
    fmt.Println(findMaximizedCapital(2, 0,
        []int{1, 2, 3}, []int{0, 1, 1})) // 4
    fmt.Println(findMaximizedCapital(3, 0,
        []int{1, 2, 3}, []int{0, 1, 2})) // 6
    fmt.Println(findMaximizedCapital(1, 0,
        []int{1, 2, 3}, []int{1, 1, 2})) // 0
}
```
