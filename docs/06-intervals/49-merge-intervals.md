# 49. 合并区间

## 题目描述

以数组 `intervals` 表示若干个区间的集合，其中单个区间为 `intervals[i] = [start_i, end_i]`。请你合并所有重叠的区间，并返回 **一个不重叠的区间数组，该数组需恰好覆盖输入中的所有区间**。

**示例 1：**

```
输入：intervals = [[1,3],[2,6],[8,10],[15,18]]
输出：[[1,6],[8,10],[15,18]]
解释：区间 [1,3] 和 [2,6] 重叠, 将它们合并为 [1,6]
```

**示例 2：**

```
输入：intervals = [[1,4],[4,5]]
输出：[[1,5]]
解释：区间 [1,4] 和 [4,5] 可被视为重叠区间
```

**约束条件：**

- `1 <= intervals.length <= 10^4`
- `intervals[i].length == 2`
- `0 <= start_i <= end_i <= 10^4`

## 题目分析

### 算法思路

**核心思路：** 最朴素的做法是把区间两两比较，只要相交就合并，反复迭代直到稳定。单次合并需要 O(n²) 次比较，而且合并出新区间后要重新扫描，效率很差。

关键观察是：**如果把区间按起点排好序，那么与「当前正在合并的区间」相交的区间，必然是排序后紧挨着的一连串区间，不会中间断掉再出现。** 理由是：设当前合并区间为 `[l, r]`，下一个待处理区间为 `[s, e]`。因为已按起点排序，有 `s >= l`：

- 若 `s <= r`，则两个区间有公共点（至少 `s` 同时在两区间内），必须合并；
- 若 `s > r`，则该区间与当前区间不相交；而它后面的区间起点只会更大，也不可能与当前区间相交。

于是「排序 + 一次线性扫描」就能完成全部合并，不需要回溯，也不需要反复迭代。

**算法步骤（不变量：`merged` 中已存放的区间两两不重叠、按起点升序，且它们的并集恰好等于「已处理区间」的并集）：**

1. 空数组直接返回。
2. 用 `sort.Slice` 把所有区间按**起点**升序排序。
3. 把第一个区间放入结果 `merged`。
4. 依次考察剩下的每个区间 `curr`，令 `last` 为 `merged` 的最后一个区间：
   - 若 `curr[0] <= last[1]`，说明二者相交（闭区间，端点相等也算相交，见示例 2），把 `last[1]` 更新为 `max(last[1], curr[1])`；
   - 否则二者不相交，把 `curr` 追加为新的最后一个区间。
5. 返回 `merged`。

**为什么正确：**

- **不变量保持**：情形一的更新只改变了 `last` 的右端点，`merged` 中其余区间不变；因为 `curr[0] >= last[0]` 且更新后右端点不小于原来的值，`last` 之前不会与更早的区间产生新的重叠，`merged` 依然有序不重叠，而并集是 `原来的并集 ∪ curr`。情形二追加 `curr` 后，由上面的观察可知 `curr` 与 `merged` 中所有区间都不相交（`curr[0] > last[1]`，而更早区间的右端点不大于 `last[1]`），并集同样正确扩展。
- **合并右端点要取最大值**：当 `curr` 被 `last` 完全包含时（例如 `last=[1,10]`、`curr=[2,3]`），并集仍是 `[1,10]`，所以必须取 `max`，不能直接赋值 `curr[1]`。
- **终点处的正确性**：扫描结束时所有区间都并入过 `merged`，所以 `merged` 的并集就是全部输入的并集，且它两两不重叠，正是题目要的答案。

### 复杂度分析

- **时间复杂度**：O(n log n)。瓶颈在排序；扫描是 O(n)。
- **空间复杂度**：O(n) 用于存放结果；排序本身若不计入结果，只需 O(log n) 的递归栈（`sort.Slice` 不额外申请数组）。

### 易错点 / 边界情况

- **相交判据是闭区间**：`curr[0] <= last[1]` 中的等号不能省，示例 2 的 `[1,4]` 与 `[4,5]` 只共享端点 `4`，也必须合并。
- **合并时要求 `max` 而不是覆盖**：只写 `last[1] = curr[1]` 会在「新区间被旧区间包含」时把区间缩小，结果出错。
- **只按起点排序**：比较函数写成 `intervals[i][0] < intervals[j][0]`。如果误按终点排序，上面「相交区间连续」的论证就不成立。
- **代码会原地修改输入**：排序打乱了 `intervals` 的顺序，而且 `last[1] = ...` 会改动 `intervals` 内部切片的元素（`merged` 与输入共享底层数组）。LeetCode 评测允许这种写法，但调用方若还要复用原数组，需要先自行深拷贝。
- **空输入**：约束允许 `intervals.length == 0`，需要提前返回，否则会 panic。
- **区间长度固定为 2**：不要臆想不存在的一维区间表示。
- **端点相等但区间不重叠的判定**：`[1,2]` 与 `[3,4]` 起点 3 > 右端 2，正确判为不重叠，不会误合并。

## Go 代码实现

```go
import "sort"

func merge(intervals [][]int) [][]int {
    if len(intervals) == 0 {
        return nil
    }

    // 按照区间起点升序排列
    sort.Slice(intervals, func(i, j int) bool {
        return intervals[i][0] < intervals[j][0]
    })

    // 初始化结果，放入第一个区间
    merged := [][]int{intervals[0]}

    for i := 1; i < len(intervals); i++ {
        last := merged[len(merged)-1]
        curr := intervals[i]

        // 当前区间与最后一个结果区间重叠
        if curr[0] <= last[1] {
            // 合并：更新终点为两者终点的最大值
            if curr[1] > last[1] {
                last[1] = curr[1]
            }
        } else {
            // 不重叠，直接加入
            merged = append(merged, curr)
        }
    }

    return merged
}
```
