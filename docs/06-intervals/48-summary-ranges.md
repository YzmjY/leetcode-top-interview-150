# 48. 汇总区间

## 题目描述

给定一个 **无重复元素** 的 **有序** 整数数组 `nums`。

返回 **恰好覆盖数组中所有数字** 的 **最小有序** 区间范围列表。也就是说，`nums` 的每个元素都恰好被某个区间范围所覆盖，并且不存在属于某个范围但不属于 `nums` 的数字 `x`。

列表中的每个区间范围 `[a,b]` 应该按如下格式输出：
- `"a->b"`，如果 `a != b`
- `"a"`，如果 `a == b`

**示例 1：**

```
输入：nums = [0,1,2,4,5,7]
输出：["0->2","4->5","7"]
解释：区间范围是：
[0,2] --> "0->2"
[4,5] --> "4->5"
[7,7] --> "7"
```

**示例 2：**

```
输入：nums = [0,2,3,4,6,8,9]
输出：["0","2->4","6","8->9"]
解释：区间范围是：
[0,0] --> "0"
[2,4] --> "2->4"
[6,6] --> "6"
[8,9] --> "8->9"
```

**约束条件：**

- `0 <= nums.length <= 20`
- `-2^31 <= nums[i] <= 2^31 - 1`
- `nums` 中的所有值都 **互不相同**
- `nums` 按升序排列

## 题目分析

### 算法思路

**核心思路：** 一个朴素的想法是：对于每个数字，都去问「它和下一个数字是不是相差 1」。如果相差 1 就并入当前区间，否则就收尾开新区间。这个想法能成立的前提是数组**已经有序且没有重复元素**——此时「所有连续整数」在数组中必然占据一段**连续的下标区间**，不会出现「2,3 在数组开头、4 在数组结尾」这种被拆散的情况。正因为如此，才不需要哈希表去记录「每个数是否出现过」，只要一次线性扫描就够。

另一个直接的想法是「从 `nums[0]` 开始累加递增，看下一个数等不等于上一个数 +1」，这其实就是同一件事，只是把判断写在了相邻两个元素上。

**算法步骤（外层循环的不变量：每轮开始时，`nums[0..i-1]` 已被完整划分成若干区间，且 `i` 是剩余部分的下标最小的元素）：**

1. 若数组为空，直接返回空结果（本题 `n == 0` 时返回 `nil`）。
2. 用 `i` 指向当前区间的起点，记 `start = nums[i]`。
3. 内层循环把 `i` 一直向后推：只要 `i < n` 且 `nums[i] == nums[i-1] + 1`，就说明 `nums[i]` 仍属于当前连续段，继续推进。
4. 内层循环退出时，`i` 已经越过当前连续段的末尾，因此 `end = nums[i-1]` 就是该段的终点。
5. 若 `start == end`，输出 `"start"`；否则输出 `"start->end"`。
6. 回到第 2 步继续处理剩余元素，直到 `i == n`。

**为什么正确：** 分两点论证。

- **覆盖性与不重复性**：外层每轮把 `nums[start 所在下标 .. i-1]` 划为一个区间；内层循环的条件保证这段中任意相邻两个元素都相差 1，即它们恰好是连续整数；而内层退出说明 `nums[i]` 与段尾不相邻，所以下一段的起点与上一段终点之间必然缺了至少一个整数。因此每个元素恰好被一个区间覆盖，且任意两个区间不会跨越同一个整数。这同时说明输出符合题干「每个元素恰好被覆盖、且区间内不含不属于 `nums` 的数字」。
- **最小性**：题目要的区间端点都必须取自 `nums`（否则会覆盖不属于 `nums` 的数字）。既然两个相邻元素只要相差 1 就必须放进同一个区间（否则区间里会缺一个 `nums` 中的数字），那么划分方式实际上是被数组唯一确定的，算法给出的正是这个唯一划分，因此区间数量最少。

### 复杂度分析

- **时间复杂度**：O(n)。虽然有两层循环，但内层循环把 `i` 单调地推过整个数组，`i` 总共只前进 n 次，外层循环的每次迭代至少消耗一个元素，所以总操作次数是 O(n)。
- **空间复杂度**：O(1) 额外空间（不计输出列表）。字符串是逐条生成的，除了结果本身没有别的数组或哈希表。若把输出计入，则是 O(m)，m 为区间个数。

### 易错点 / 边界情况

- **末尾的 `end = nums[i-1]` 容易写错**：内层循环结束时 `i` 指向的是「下一段的第一个元素」或 `n`，真正的终点在 `i-1`。如果在循环里先取 `end` 再推进 `i`，或写成 `nums[i]`，就会越界或取错值。
- **空数组**：约束允许 `nums.length == 0`，必须单独返回，否则第 2 步访问 `nums[0]` 会 panic。
- **终点判断不要写成 `nums[i+1]`**：写成「检查 `nums[i] + 1 == nums[i+1]`」需要在循环中处理 `i+1 == n` 的越界；本题写法改为「检查 `nums[i] == nums[i-1] + 1`」，只在 `i < n` 时求值，天然安全。
- **`nums[i-1] + 1` 的溢出**：当 `nums[i-1] == 2^31-1`（题目允许的最大值）时，在 32 位平台上加 1 会回绕成负数；即使在 64 位平台得到 `2^31`，由于数组严格升序、不存在比 `2^31-1` 更大的元素，`nums[i] == nums[i-1]+1` 也必然为假。两种情况下结果都正确，但这属于「恰好正确」，理解时要想清楚为什么不需要特判。
- **单元素数组**：输出应是不带箭头的 `"a"`，注意 `start == end` 分支。
- **不要漏掉负数**：`Itoa` 会自动处理负号，别对值做特殊假设。
- **结果顺序**：本题输出是有序的，不存在「任意顺序」的余地，测试时按顺序比较即可。

## Go 代码实现

```go
import "strconv"

func summaryRanges(nums []int) []string {
    n := len(nums)
    if n == 0 {
        return nil
    }

    var result []string

    for i := 0; i < n; {
        // 当前区间的起点
        start := nums[i]

        // 不断向后移动，直到连续被打破
        for i++; i < n && nums[i] == nums[i-1]+1; i++ {
        }

        // 当前区间的终点
        end := nums[i-1]

        // 根据起点和终点生成对应的字符串
        if start == end {
            result = append(result, strconv.Itoa(start))
        } else {
            result = append(result, strconv.Itoa(start)+"->"+strconv.Itoa(end))
        }
    }

    return result
}
```
