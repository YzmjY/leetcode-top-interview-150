# 102. 组合

## 题目描述

给定两个整数 `n` 和 `k`，返回范围 `[1, n]` 中所有可能的 `k` 个数的组合。

你可以按**任何顺序**返回答案。

**示例 1：**

```
输入：n = 4, k = 2
输出：
[
  [2,4],
  [3,4],
  [2,3],
  [1,2],
  [1,3],
  [1,4],
]
```

**示例 2：**

```
输入：n = 1, k = 1
输出：[[1]]
```

**约束条件：**

- `1 <= n <= 20`
- `1 <= k <= n`

## 题目分析

### 算法思路

**核心思路**：组合与排列的核心区别是**组合不考虑顺序**，`[1,2]` 和 `[2,1]` 是同一个组合。因此只要规定「每个组合中的数字按递增顺序排列」，就得到唯一的表示，不需要再去重。

**避免重复的关键：`start` 参数。** 递归函数 `backtrack(start)` 表示「接下来只能从 `start..n` 中选数」。第 `i` 层选了数字 `x` 后，下一层从 `x+1` 开始选。这样每条搜索路径上的数字严格递增，任何一个组合只会被生成一次。

**算法步骤：**

1. `path` 记录当前部分组合（`make([]int, 0, k)`）。
2. `backtrack(start)`：
   - 若 `len(path) == k`，把 `path` 拷贝一份加入 `result`，返回；
   - 否则 `for i := start; i <= n-(k-len(path))+1; i++`：把 `i` 压入 `path`，递归 `backtrack(i+1)`，返回后弹出 `i`（回溯）。
3. 从 `backtrack(1)` 开始。

**剪枝的推导：** 还差 `k - len(path)` 个数字没选，而当前可选的区间 `[i, n]` 里共有 `n - i + 1` 个数。只有 `n - i + 1 >= k - len(path)` 才可能凑够，整理得 `i <= n - (k - len(path)) + 1`，这就是循环上界的来源。

### 为什么正确

- **不重**：每条从根到叶子的路径上数字严格递增，而一个 `k` 元组合按递增排列只有一种写法，所以每个组合至多被生成一次——不同的生成路径必然对应不同的递增序列。
- **不漏**：设 `{a1 < a2 < ... < ak}` 是任意一个组合。第 1 层循环从 `start=1` 枚举，必然能选到 `a1`；此后下一层从 `a1+1` 开始，必然能选到 `a2`；依此类推直到 `ak` 被选中，于是该组合一定会被输出。剪枝只砍掉了「剩余数字不足以选够 `k` 个」的分支，这些分支本就不可能产出合法解，所以不漏解。
- **长度正确**：只有 `len(path) == k` 时才收集，保证每个结果恰好 `k` 个元素。
- **独立拷贝**：`path` 是复用的切片，必须 `copy` 到新切片再收集，否则所有结果会共享同一底层数组。

### 复杂度分析

- **时间复杂度：** O(C(n,k) × k)。搜索树的叶子数等于组合数 `C(n,k)`，每个叶子要做一次 O(k) 的拷贝；内部节点的开销与之同阶（每个内部节点至少对应一个叶子）。
- **空间复杂度：** O(k)，`path` 的长度与递归栈深度都不超过 k（不计存放答案的空间）。

### 易错点 / 边界情况

- **循环上界**：写成 `i <= n-(k-len(path))+1` 而不是 `i <= n`，少了剪枝会做无用功；写成 `n-(k-len(path))` 则会漏解。
- **结果是独立拷贝**：收集时必须 `tmp := make([]int, k); copy(tmp, path)`，直接 `append(result, path)` 会让所有结果指向同一块内存，最后一个组合会覆盖全部。
- **回溯要弹出元素**：`path = path[:len(path)-1]` 不能漏；由于 `path` 是复用的切片，忘记弹出会让后续分支带着多余的数继续。
- **`k == n`**：此时只有唯一组合 `[1..n]`，剪枝上界恰好让循环只执行一次。
- **`k == 1`**：循环上界为 `n`，结果是 `[[1],[2],...,[n]]`。
- **返回顺序**：题目允许任意顺序；本仓库代码的输出是按字典序的 `[[1,2],[1,3],[1,4],[2,3],[2,4],[3,4]]`，与示例给出的顺序不同，但两者都正确。
- **`n <= 20`**：组合数最大约 `C(20,10) = 184756`，结果总量可控，不需要额外优化。

## Go 代码实现

```go
package main

import "fmt"

// combine 生成 1..n 的所有 k 个数的组合
func combine(n int, k int) [][]int {
    result := [][]int{}
    path := make([]int, 0, k)

    var backtrack func(start int)
    backtrack = func(start int) {
        // 收集结果
        if len(path) == k {
            tmp := make([]int, k)
            copy(tmp, path)
            result = append(result, tmp)
            return
        }

        // 剪枝：剩余元素不足
        // 还需要 k - len(path) 个，剩余 n - i + 1 个
        for i := start; i <= n-(k-len(path))+1; i++ {
            path = append(path, i)
            backtrack(i + 1)
            path = path[:len(path)-1]
        }
    }

    backtrack(1)
    return result
}

func main() {
    fmt.Println(combine(4, 2))
    // [[1 2] [1 3] [1 4] [2 3] [2 4] [3 4]]
    fmt.Println(combine(1, 1))
    // [[1]]
}
```
