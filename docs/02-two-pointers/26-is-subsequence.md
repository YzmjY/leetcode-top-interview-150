# 26. 判断子序列

## 题目描述

给定字符串 `s` 和 `t`，判断 `s` 是否为 `t` 的子序列。

字符串的一个子序列是原始字符串删除一些（也可以不删除）字符而不改变剩余字符相对位置形成的新字符串。（例如，`"ace"` 是 `"abcde"` 的一个子序列，而 `"aec"` 不是）。

**示例 1：**

```
输入：s = "abc", t = "ahbgdc"
输出：true
```

**示例 2：**

```
输入：s = "axc", t = "ahbgdc"
输出：false
```

**约束条件：**

- `0 <= s.length <= 100`
- `0 <= t.length <= 10^4`
- 两个字符串都只由小写字符组成。

**进阶：** 如果有大量输入的 S，称作 S1, S2, ..., Sk 其中 k >= 10亿，你需要依次检查它们是否为 T 的子序列。在这种情况下，你会怎样改变代码？

## 题目分析

**算法思路：** 子序列要求字符在 `t` 中按原顺序出现，允许跳过任意多的字符。朴素想法是：对 `s` 的每个字符，从 `t` 中上一次匹配位置之后继续往后找。这正好可以用两个同向指针——`i` 指向 `s` 中下一个待匹配的字符，`j` 顺序扫过 `t`，`t[j] == s[i]` 时就让 `i` 前进。这里隐含一个贪心选择：`t[j]` 只要能匹配 `s[i]` 就必须匹配，因为用最靠前的位置匹配 `s[i]`，会给后续字符留下最多的可用字符，不会比往后拖更差。

**算法步骤：**

1. `i = 0`，代表 `s` 中待匹配的下标。
2. `j` 从 0 遍历到 `len(t)-1`，只要 `i < len(s)`：若 `s[i] == t[j]` 则 `i++`；无论是否匹配，`j` 都继续自增。
3. 循环结束后判断 `i == len(s)`：成立说明 `s` 的所有字符都按顺序在 `t` 中找到了。

**为什么正确（贪心选择性质）：** 假设 `s` 确实是 `t` 的子序列。归纳地看，贪心算法维护的 `i` 是不劣于任何匹配方案所能匹配到的 `s` 的前缀长度：若 `t[j] == s[i]`，`j` 之前的字符都不等于 `s[i]`，所以任何可行方案也只能用某个 `j' >= j` 的位置来匹配 `s[i]`，而选择更靠前的 `j` 给后续留下的区间是更靠后选择所得区间的超集，因此贪心不会把可行解逼到不可行。所以只要存在匹配，贪心必然能走完 `s`。反过来，若贪心结束时 `i < len(s)`，说明 `s[i]` 在 `t` 的剩余部分中从未出现过，任何方案都无法匹配，返回 `false` 正确。

**时间复杂度：** O(len(t))。`j` 单向前进扫过 `t`，一旦 `s` 匹配完就提前退出；`i` 也只会前进。

**空间复杂度：** O(1)，只用两个下标。

**易错点：**

- 判断依据必须是 `i == len(s)`，只匹配到一部分会误判为真。
- `s` 为空串时是任何串的子序列，返回 `true`；`t` 为空而 `s` 非空时返回 `false`。
- 不能用「各字符出现次数是否足够」代替顺序判断：`s = "abc"`、`t = "acb"` 计数相同，但 `s` 不是 `t` 的子序列。
- 两次循环的边长都要注意：外层按 `t` 走、内层比较 `s[i]`，别把两者写反；题目限定小写字母，逐字节比较即可。

## Go 代码实现

```go
// isSubsequence 判断 s 是否为 t 的子序列
// 使用同向双指针
func isSubsequence(s string, t string) bool {
    // i 指向 s 中待匹配的字符
    i := 0
    // j 遍历 t
    for j := 0; j < len(t) && i < len(s); j++ {
        // 找到匹配字符，s 的指针后移
        if s[i] == t[j] {
            i++
        }
        // 注意：即使不匹配，j 也会在循环中自增
    }
    // s 的所有字符都被匹配到，说明是子序列
    return i == len(s)
}
```
