# 144. 不同路径 II (Unique Paths II)

## 题目描述

一个机器人位于一个 `m x n` 网格的左上角（起始点在下图中标记为 "Start"）。

机器人每次只能向下或者向右移动一步。机器人试图达到网格的右下角（在下图中标记为 "Finish"）。

现在考虑网格中有障碍物。那么从左上角到右下角将会有多少条不同的路径？

网格中的障碍物和空位置分别用 `1` 和 `0` 来表示。

**示例 1：**

```
输入：obstacleGrid = [[0,0,0],[0,1,0],[0,0,0]]
输出：2
解释：3x3 网格的正中间有一个障碍物。
从左上角到右下角一共有 2 条不同的路径：
1. 向右 -> 向右 -> 向下 -> 向下
2. 向下 -> 向下 -> 向右 -> 向右
```

**示例 2：**

```
输入：obstacleGrid = [[0,1],[0,0]]
输出：1
```

**约束条件：**

- `m == obstacleGrid.length`
- `n == obstacleGrid[i].length`
- `1 <= m, n <= 100`
- `obstacleGrid[i][j]` 为 `0` 或 `1`

**说明：** 测试用例保证答案小于等于 `2 * 10^9`（即不会超出 32 位有符号整数范围）。

## 题目分析

### 算法思路

**关键观察。** 本题与「不同路径 I」结构完全相同：机器人只会向右/向下移动，到达 `(i, j)` 的最后一步
只能来自上方或左方，路径被最后一步的方向唯一分成两类，互不重复，因此路径数满足加法原理。
障碍物带来的唯一变化是：**障碍格自身不可达（路径数记为 0），并且任何经过它的路径都不存在** ——
而这一点会被转移公式自动传播，因为后续格子求和时加上的就是 0。

- **状态定义**：`dp[i][j]` = 从起点 `(0, 0)` 走到 `(i, j)` 的不同路径数。
- **状态转移**：
  - 若 `obstacleGrid[i][j] == 1`（障碍）：`dp[i][j] = 0`；
  - 否则 `dp[i][j] = dp[i-1][j] + dp[i][j-1]`（越界的一侧视为 0，等价于第一行/第一列只有一条路）。
- **边界条件**：`dp[0][0] = 1`（前提是起点不是障碍物）。起点本身是障碍物时，答案必为 0。

**为什么正确。** 对任意非障碍格 `(i, j)`，一条从起点到它的路径按最后一步方向分成两类：
从上方 `(i-1,j)` 下来、或从左方 `(i,j-1)` 过来，两类路径互不重复且恰好覆盖全部路径，
所以路径数等于两类之和——这正是不含障碍时的转移式。障碍格的路径数定义为 0，
表示没有任何合法路径能落在该格上，这与「移动路径中不能包含障碍格」一致。
按行列递增的顺序递推，每个子问题在使用前已算好，归纳可得 `dp[m-1][n-1]` 为答案。

注意障碍物对第一行/第一列的影响是自动处理的：第一行只能从左来，累加链一旦遇到障碍就被置 0，
其右侧所有格子随之保持 0；第一列同理。

**空间优化（一维滚动数组）。** 代码用一个长度为 `n` 的数组 `dp` 代替二维表：

- 进入第 `i` 行时，`dp[j]` 是上一行的值 `dp[i-1][j]`（上方），`dp[j-1]` 已被本行覆盖为 `dp[i][j-1]`（左方），
  所以非障碍格且 `j > 0` 时执行 `dp[j] += dp[j-1]`；
- `j == 0` 时没有左方：非障碍格保持 `dp[0]` 不变（相当于从上方继承），障碍格置 0；
- 初始 `dp[0] = 1`，表示起点本身有一条「空路径」；这也让第一列在遇到障碍前始终保持 1。

**关于提前返回。** 代码开头 `if obstacleGrid[0][0] == 1 || obstacleGrid[m-1][n-1] == 1 { return 0 }`
只是一个剪枝：一维 DP 本身也能正确得到 0（起点会被置 0，终点会被置 0），所以这一判断不是必需的。

### 复杂度分析

- **时间复杂度**：O(m·n)，每个格子做一次常数时间的加法或赋值。
- **空间复杂度**：O(n)，只保留一行；若使用完整二维表则为 O(m·n)。

### 关键点

- 障碍物「归零」是关键操作：它同时表达「该格不可达」和「阻断所有经过它的路径」两层含义。
- 起点或终点是障碍物时答案是 0，属于必须覆盖的边界。
- 「第一行/第一列一旦受阻，后面的格子全部不可达」不需要额外特判，但理解这一点才能确信代码正确。
- 路径数的范围：`m, n ≤ 100` 时无障碍的路径数理论上可达 C(198,99) 量级，远超 32 位整数；
  题面保证**答案** ≤ 2×10⁹。对任何仍能通向终点的格子 `(i, j)`，它的路径数不会超过答案
  （每条到达它的路径都能延展成一条到终点的路径），因此与最终答案相关的 dp 值都在 32 位范围内；
  Go 的 `int` 在 64 位平台上是 64 位，足够安全。

## Go 代码实现

```go
package main

func uniquePathsWithObstacles(obstacleGrid [][]int) int {
    m, n := len(obstacleGrid), len(obstacleGrid[0])

    // 如果起点或终点是障碍物，直接返回 0
    if obstacleGrid[0][0] == 1 || obstacleGrid[m-1][n-1] == 1 {
        return 0
    }

    // 一维 DP 数组
    dp := make([]int, n)
    dp[0] = 1 // 起点

    for i := 0; i < m; i++ {
        for j := 0; j < n; j++ {
            if obstacleGrid[i][j] == 1 {
                dp[j] = 0 // 障碍物，路径数为 0
            } else if j > 0 {
                dp[j] += dp[j-1] // 上方(dp[j]) + 左方(dp[j-1])
            }
            // j == 0 时，dp[j] 保持不变（第一列只能从上方来）
        }
    }

    return dp[n-1]
}
```
