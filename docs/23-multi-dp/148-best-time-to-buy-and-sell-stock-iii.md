# 148. 买卖股票的最佳时机 III (Best Time to Buy and Sell Stock III)

## 题目描述

给定一个数组，它的第 `i` 个元素是一支给定的股票在第 `i` 天的价格。

设计一个算法来计算你所能获取的最大利润。你最多可以完成 **两笔** 交易。

**注意：** 你不能同时参与多笔交易（你必须在再次购买前出售掉之前的股票）。

**示例 1：**

```
输入：prices = [3,3,5,0,0,3,1,4]
输出：6
解释：在第 4 天（股票价格 = 0）的时候买入，在第 6 天（股票价格 = 3）的时候卖出，这笔交易所能获得利润 = 3-0 = 3 。
     随后，在第 7 天（股票价格 = 1）的时候买入，在第 8 天 （股票价格 = 4）的时候卖出，这笔交易所能获得利润 = 4-1 = 3 。
```

**示例 2：**

```
输入：prices = [1,2,3,4,5]
输出：4
解释：在第 1 天（股票价格 = 1）的时候买入，在第 5 天 （股票价格 = 5）的时候卖出, 这笔交易所能获得利润 = 5-1 = 4 。
     注意你不能在第 1 天和第 2 天接连购买股票，之后再将它们卖出。
     因为这样属于同时参与了多笔交易，你必须在再次购买前出售掉之前的股票。
```

**示例 3：**

```
输入：prices = [7,6,4,3,1]
输出：0
解释：在这个情况下, 没有交易完成, 所以最大利润为 0。
```

**示例 4：**

```
输入：prices = [1]
输出：0
```

**约束条件：**

- `1 <= prices.length <= 10^5`
- `0 <= prices[i] <= 10^5`

## 题目分析

### 算法思路

**关键观察。** 每天结束时，决定「接下来还能做什么」的信息只有两件：已经完成了多少笔交易、当前是否持股。
具体的买卖日期不影响后续决策（无后效性），因此可以用少数几个变量表示各种「处境」下的最大利润。
本题最多两笔交易，于是恰好四个状态：

- `buy1`：完成**第一次买入**后的最大利润（此时持有股票，现金为负）；
- `sell1`：完成**第一次卖出**后的最大利润（此时空仓、已完成 1 笔）；
- `buy2`：完成**第二次买入**后的最大利润（持有股票、已完成 1 笔）；
- `sell2`：完成**第二次卖出**后的最大利润（空仓、已完成 2 笔），也就是最终答案。

**状态转移（按天推进）。** 对当天的价格 `p`：

- `buy1 = max(buy1, -p)`：要么之前就已完成第一次买入，要么今天第一次买入（利润 `-p`）；
- `sell1 = max(sell1, buy1 + p)`：要么之前已完成第一次卖出，要么在「已买入」的状态上今天卖出，得 `buy1 + p`；
- `buy2 = max(buy2, sell1 - p)`：要么之前已第二次买入，要么在「第一次已卖出」的状态上今天买入，得 `sell1 - p`；
- `sell2 = max(sell2, buy2 + p)`：同理，第二次卖出。

**初始值**：`buy1 = buy2 = -∞`（表示「尚未买入」这个状态不能直接用于卖出），`sell1 = sell2 = 0`。
代码用 `math.MinInt32` 表示 `-∞`。

**为什么正确。** 四个式子都是「按当天的动作分类」：以 `sell1` 为例，最优方案要么在更早的某天完成了第一次卖出
（今天什么都不做，值不变），要么今天就是第一次卖出的日子（此时此前必然是「已完成第一次买入」状态，
由 `buy1 + p` 转移）。两类覆盖全部情况，取最大值即为当天结束时的最优。其余三个状态同理。
每天按 `buy1 → sell1 → buy2 → sell2` 的顺序更新，同一个价格可以连续参与多次转移，
这对应题目允许「同一天卖出后再买入」（`sell1 - p` 用的是今天的 `sell1`）。
当日买卖的收益为 0，不会虚增利润，只是允许把两笔交易安排在同一天切换。
对天数归纳可知遍历结束后 `sell2` 就是「最多两笔交易」的最大利润。

**补充理解：同日买卖不影响答案。** 在价格 `p` 处卖出再买回，相当于把前后两笔交易合并成一笔，总利润相同，
只是多占一次交易名额。因此允许同日操作不会给出比「严格隔天」更大的利润，最优解总能只用 ≤ 2 笔完成。

### 复杂度分析

- **时间复杂度**：O(n)，一次遍历，每天做 4 次比较与加法。
- **空间复杂度**：O(1)，只用 4 个变量（不需要按天或按交易次数开数组）。
- 数值范围：n ≤ 10⁵、价格 ≤ 10⁵，两笔交易的利润上界约 2×10⁵，`int` 足够；
  `math.MinInt32 ± p` 在 64 位 `int` 上也不会溢出。

### 关键点

- 初始值必须让「买入态」为 `-∞`（`math.MinInt32`）而不是 0：0 相当于「白赚一笔」，会让答案偏大。
- 四个状态按 `buy1 → sell1 → buy2 → sell2` 的顺序更新，使同一个价格可以连续参与多次转移，
  即允许「同一天卖出后再买入」（题目规则允许）。若把顺序换成「卖出后必须隔天才买」，最优值其实不变
  （当日一卖一买等价于把前后两笔合并成一笔，见上文），但标准写法更贴近题意。
- 答案是 `sell2`，其初值为 0，所以「一笔都不做」也是合法方案；最多两笔不需要做满两笔。
- 只有一天、或价格单调下跌时答案为 0，属于必须覆盖的边界。
- 等价思路（可作对照）：枚举分割点 `i`，用一趟「最多 1 笔」的前缀最优 + 后缀最优拼起来，
  也能得到 O(n) 的解法，但要多做一次遍历；状态机写法更直接、更容易推广到 k 笔（见第 149 题）。

## Go 代码实现

```go
package main

import "math"

func maxProfit(prices []int) int {
    buy1 := math.MinInt32  // 第一次买入后的最大利润
    sell1 := 0              // 第一次卖出后的最大利润
    buy2 := math.MinInt32   // 第二次买入后的最大利润
    sell2 := 0              // 第二次卖出后的最大利润

    for _, price := range prices {
        buy1 = max(buy1, -price)
        sell1 = max(sell1, buy1+price)
        buy2 = max(buy2, sell1-price)
        sell2 = max(sell2, buy2+price)
    }

    return sell2
}

func max(a, b int) int {
    if a > b {
        return a
    }
    return b
}
```
