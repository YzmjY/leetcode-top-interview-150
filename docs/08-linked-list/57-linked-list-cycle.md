# 57. 环形链表

## 题目描述

给你一个链表的头节点 `head`，判断链表中是否有环。

如果链表中有某个节点，可以通过连续跟踪 `next` 指针再次到达，则链表中存在环。为了表示给定链表中的环，评测系统内部使用整数 `pos` 来表示链表尾连接到链表中的位置（索引从 0 开始）。**注意：`pos` 不作为参数进行传递**。仅仅是为了标识链表的实际情况。

如果链表中存在环，则返回 `true`。否则，返回 `false`。

**示例 1：**

```
输入：head = [3,2,0,-4], pos = 1
输出：true
解释：链表中有一个环，其尾部连接到第二个节点。
```

**示例 2：**

```
输入：head = [1,2], pos = 0
输出：true
解释：链表中有一个环，其尾部连接到第一个节点。
```

**示例 3：**

```
输入：head = [1], pos = -1
输出：false
解释：链表中没有环。
```

**约束条件：**

- 链表中节点的数目范围是 `[0, 10^4]`
- `-10^5 <= Node.val <= 10^5`
- `pos` 为 `-1` 或者链表中的一个 **有效索引**

**进阶**：你能用 O(1)（即常量）内存解决此问题吗？

## 题目分析

### 算法思路

**核心思路：** 最直接的做法是遍历链表，用一个哈希表记下访问过的节点指针；一旦再次碰到已访问的节点，就说明有环。这需要 O(n) 额外空间，不满足进阶要求。

想要 O(1) 空间，就要在「原地」发现环。想象两个人在环形跑道上跑步：**一个跑得快、一个跑得慢，只要跑道是环形的，快的人最终一定会从后面追上慢的人**；反过来，如果是直道，快的人会先到终点。这正是 Floyd 判圈算法（龟兔赛跑）。落到链表上：让 `slow` 每次走 1 步、`fast` 每次走 2 步，如果 `fast` 先走到 `nil`，说明是直道（无环）；如果两者相遇（指向同一节点），说明有环。

**算法步骤：**

1. 特判：`head == nil` 或 `head.Next == nil` 时不可能有环，直接返回 `false`。
2. `slow, fast := head, head`，两个指针都从头出发。
3. 循环：只要 `fast != nil && fast.Next != nil`，就令 `slow = slow.Next`（一步）、`fast = fast.Next.Next`（两步）。每轮检查 `slow == fast`，相等就返回 `true`。
4. 若循环因 `fast` 走到链尾而退出，返回 `false`。

**为什么正确：**

- **无环时**：链表是一条有限长的链。`fast` 每次前进两步，只要还有节点，循环就继续；当 `fast` 或 `fast.Next` 变成 `nil` 时循环终止，此时不可能存在环（有环的话 `fast` 永远不会变成 `nil`）。所以无环时一定返回 `false`。
- **有环时**：设环的长度为 L。当 `slow` 也进入环之后，两个指针都在环上运动。`slow` 每轮走 1 步、`fast` 每轮走 2 步，因此以 `slow` 为参照，`fast` 每轮朝它靠近 1 步。设某一轮开始时 `fast` 落后 `slow` 的距离为 `d ∈ [0, L)`（把环展开成直线，距离指沿运动方向从 `slow` 走到 `fast` 的步数），则每经过一轮 `d` 变为 `(d-1) mod L`。于是至多 L 轮之后 `d = 0`，两指针相遇。因为 `fast` 是一步一步（相对而言）追近的，**不存在「跳过去」的情况**，所以「相遇」这一事件在有环时必然发生。
- **时间有界**：`slow` 进入环需要至多 n 步，之后至多 L <= n 步就相遇，总轮数是 O(n)，因此算法不会死循环。

### 复杂度分析

- **时间复杂度**：O(n)，n 为链表中节点个数。慢指针进入环之前最多走 n 步，进入环后最多再走 L (<= n) 步即相遇。无环时快指针走到链尾同样是 O(n)。
- **空间复杂度**：O(1)，只用了两个指针，不随链表长度增长。

### 易错点 / 边界情况

- **循环条件必须同时检查 `fast` 和 `fast.Next`**：写成 `fast != nil` 就取 `fast.Next.Next`，当 `fast.Next == nil` 时会空指针 panic。
- **判据是指针相等，不是值相等**：遇到两个 `Val` 相同的节点不代表有环，务必用 `slow == fast` 比较节点身份。
- **快指针的步长必须正好是 2**：步长为 2 时相对速度是 1，在长度为 L 的环上一一靠近、必然命中。若改成每次走 3 步，相对速度变成 2，当 L 为偶数时可能每次恰好跨过慢指针，永远无法相遇——所以不要用「更快」的步长。
- **`fast` 的初始化位置**：两个指针都从头出发时，第一次比较发生在两者都移动之后，逻辑最清晰。如果先比较再移动，则 `slow == fast == head` 会导致任何非空链表都被判为有环。
- **空链表和单节点无环要特判吗？** 其实不特判也能正确：空链表时循环条件 `fast != nil` 立即为假，返回 `false`；单节点无环时 `fast.Next == nil` 也为假。代码里的提前返回只是让这两种情况更直观。
- **本题只问「有没有环」，不要顺手返回入环点**：那需要额外的一步（相遇后让一个指针回到 `head`，两者同步前进再相遇处即入环点），属于第 142 题的内容。
- **不要修改链表结构**：某些做法会试图反转链表来判断，虽然可行但会破坏输入，且不如快慢指针干净。

## Go 代码实现

```go
// ListNode 链表节点定义
type ListNode struct {
    Val  int
    Next *ListNode
}

func hasCycle(head *ListNode) bool {
    if head == nil || head.Next == nil {
        return false
    }

    // 快慢指针初始都指向头节点
    slow, fast := head, head

    // fast 每次走两步，slow 每次走一步
    for fast != nil && fast.Next != nil {
        slow = slow.Next
        fast = fast.Next.Next
        // 快慢指针相遇，说明有环
        if slow == fast {
            return true
        }
    }

    // fast 到达 nil，说明无环
    return false
}
```
